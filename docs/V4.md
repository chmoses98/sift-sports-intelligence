# SIFT v4 (phone-first preview)

v4 is the phone-first SIFT experience approved in `design/mobile-v3-redesign`, built on the real app: the same published
boards, research documents and Kalshi quotes, through the same data layer. It is **opt-in**: nothing changes for the
default (SIFT 2.0) or classic interface unless v4 is asked for.

## Opening and leaving it

| How | What it does |
| --- | --- |
| `#/v4` | Opens v4 directly (any build). Never changes a remembered preference. |
| `#/?ui=v4` | Remembers v4 in this browser (`localStorage` key `sift.ui`); classic root addresses then open v4. A classic or SIFT 2.0 choice made earlier is kept aside (`sift.ui.before-v4`). |
| "Open in SIFT 2.0" (and the SIFT 2.0 prop-research link) | A real mode exit: forgets the remembered v4 choice and gives back the classic or SIFT 2.0 choice made before v4, so a later classic address does not redirect back into v4. Any other remembered choice is left as it is. |
| `#/?ui=default` | Forgets the choice (back to the build's interface). `?ui=sift2` / `?ui=classic` switch away and replace the saved choice. |

Everything lives in `src/v4/` and is one lazy chunk; its CSS is scoped under `.v4`, so it cannot reach the other
interfaces. Fonts (Geist Sans, Sora) are loaded only by that chunk.

## Game tabs

A game opens on **Matchups** before kickoff and on **Live** for every other state: in play (the live state), final (the
published score and a result line, when the publication reports both numbers), and awaiting result, postponed, cancelled
or suspended (the status is explained there; Matchups would show pregame research as if it were current). The default is
decided once when the game first loads and held, so a game that kicks off while it is open does not switch tabs under the
viewer. A tab the viewer chooses is written to the address (`?tab=`), wins over the default, and survives status updates and
reloads; changing tabs replaces the history entry, so Back leaves the game rather than stepping through tabs.

## What is in milestone 1

- **Shell** (`V4Root.tsx`): five tabs (Home, Games, Props, Signals, Board) on React Router, safe-area aware, one sheet host.
- **Home** (`Home.tsx`): league selector, date strip, Following / All / Live / Signals, featured game, live / upcoming /
  final groups, compact rows, signal chips.
- **Games** (`Games.tsx`): the whole day by league with a status filter.
- **Game Command Center** (`Game.tsx`): scoreboard and Live / Matchups / Players / Markets.
- **Research sheet** (`ResearchSheet.tsx`): one published opportunity: why, price against the model, strongest published
  risk, then evidence / risks / prices / sources on request.
- **Props** (milestone 2A), **Signals** (milestone 2B) and **Board** (milestone 2C), below. **Board** (milestone 2C, below).

## Props (milestone 2A)

The Props tab is the player-first Prop Explorer; each row opens a player detail, and prop rows open research sheets that can be saved to My Board.

| Piece | Where | Reuses |
| --- | --- | --- |
| Explorer: sport (NFL, MLB, NHL), game, prop category, search, ranking | `src/v4/Props.tsx`, `propsModel.ts`, `propsData.ts` | `useSlateProps` (views/props/slate), `propBoard` (insights/propBoard), `rankSlate` / `propAuthority` (views/props/ranking), `loadAuthority` (data/projections), live quotes (live/overlay) |
| Player detail: line, the one SIFT projection, the Kalshi ladder with the model on the same side, range, matchup, recent form, sources | `PropDetail.tsx`, `PropParts.tsx` | `propBoard` rows, `lib/projectionAuthority`, `history/*` game logs, `opportunity/pricing` (fee, break-even) |
| Research sheet for a prop | `PropSheet.tsx`, `ResearchSheet.tsx` | The `Opportunity` contract: a published opportunity on that exact contract opens the existing sheet; otherwise research-only details with no manufactured signal |
| Save | `SaveControl.tsx`, `saveSide.ts` | `state/tray` (the research tray, one `TrayProvider` mounted in `V4Root`): the same MARKET item, label and link as the app's SaveButton; frozen after kickoff. The selected side is recorded: the over (YES) keeps the identity every earlier save of that market has, the under (NO) is a separate item (`extra.x = 'side=NO'`) whose label reads "Name under 6.5 receptions" and whose `label.side` makes My Board compare the NO ask, not the YES ask. Saves made before sides existed read as YES, as they always did. |

Rules held: one projection per metric (the authority's); a withheld or unapproved projection shows its reason and no number, and nothing is substituted; Kalshi prices and model figures are always labelled apart; a price is executable only when its capture is FRESH or AGING (15 / 30 minute rule), otherwise it is shown greyed as context and no difference is computed; the difference is model minus break-even after Kalshi's fee, on the same side, in points, never coloured buy or sell; the difference is never graded by size (there is no "close" band or cut-off for "meaningful"): the sheet says "Model below / at / above break-even" with the number, and a positive difference is described as validated only where the opportunity layer holds a published signal for that exact market AND side (YES/NO) that is still valid at the current time (`src/v4/signal.ts`: status, authority, price state, quote age, validity window, lifecycle, contract identity). A signal for the other side, a PASS decision, or a signal that has gone stale is stated as exactly that and never shown as a signal for the side being read; stronger claims live only inside the published research sheet, which carries the publication's own uncertainty and calibration; missing values are dashes or words, never zero; pregame research is frozen after kickoff (no new saves). MLB and NHL have no approved simulated player projection, so the explorer lists their games with player-market counts and links to the game's Markets tab. Which approved NBA, MLB and NHL feeds could later support full player research is audited in [V4_PROJECTION_COVERAGE.md](V4_PROJECTION_COVERAGE.md); nothing in it is activated.

Information sources used: the NFL publication's board, event research and event detail documents; the projection feed read by `loadAuthority`; Kalshi quotes through the app's live provider (publication captures where no newer quote exists); the public game logs the history layer reads; the opportunity layer's published opportunities.

## Signals (milestone 2B)

The Signals tab is a research inbox over the app's own opportunity layer. It builds nothing new: every row is an `Opportunity` from `useAllOpportunities`, ordered and grouped by `compareOpportunities` / `featureOpportunities` (`src/opportunity/rank.ts`), opened in the existing `ResearchSheet`, saved through `SaveControl` + `sideExtra`.

| Piece | Where | Reuses |
| --- | --- | --- |
| Feed, filters, cards, verdicts | `src/v4/Signals.tsx` | `useAllOpportunities` (load.ts), `Featured` (rank.ts), `gameRows` (views/broadcast/games), `SportVerdict` / `passReasonFor` |
| Pure model: standing, filters, coverage, addresses | `src/v4/signalsModel.ts` | `featureOpportunities`, `compareOpportunities`, `ineligibleWhy` (v4/signal.ts) |
| Sheet states where a signal stands now and links back to the feed | `src/v4/ResearchSheet.tsx` | the same `standingOf` |

**Groups** (each opportunity is placed from its published fields, re-read against the clock every 30 s):
- **Current signals**: ACTIONABLE or RESEARCH_CANDIDATE that passes the same eligibility as the prop sheet (pregame, identity verified, side and price agree, authority consistent, price state CURRENT, quote FRESH/AGING, validity window open). Cards say Actionable or Research candidate and show the publication's authority word.
- **Watch**: published WATCH items (today only the CFB Value Watch). Labelled "Game-level watch · no priced contract signal"; no price is shown or implied. There is no other source of "model disagreement" statuses in the contract, so none is invented.
- **No longer current** (closed by default): a flagged signal that lapsed (window expired, quote stale, game started or frozen, identity failed), or a pass about time. Each states why.
- **Passed** (closed by default): the publication judged it and said no; each keeps its own reason and is never drawn as active (no price line, no save).
- **By sport**: for every sport, what was read: signals, the publication's verdict sentence when nothing qualifies, or "publication unavailable" (a failed feed is never counted as zero signals).

**Cards** carry only: game and time, the exact contract in bet words with the YES/NO side as a pill, the published thesis (two lines), status and authority, the Kalshi ask of that side with its age, a market-beats-the-model warning when the publication's own record says so, and the app's correlation labels (related expressions, opposite outcomes, same-game exposure). Fees, break-even, uncertainty, calibration, bet-up-to and risks stay in the research sheet. No score, no EV or edge sort exists on the screen.

**Context in the address**: `#/v4/signals?sport=&game=&status=&market=&side=`. Chips edit it (replace, so Back is not polluted); `market`+`side` come from the prop research sheet, the game's research list and the sheet's "All signals on this game" link, and bring that exact contract and side into view. If the publication names the market only for the other side, the screen says so and highlights nothing.

**Tray**: the app mounts one `TrayProvider` for the classic interfaces and v4 mounts its own; they now notify each other, so a save made in v4 is on the SIFT 2.0 My Board in the same session, not only after a reload.

Sports covered are whatever the opportunity layer returns: NFL (recommendations), CFB (Value Watch), NHL, MLB, soccer and tennis (their recommendations/theses contracts); NBA and CBB publish no priced contract and show their verdict. NBA projection engines are untouched.

## Board (milestone 2C)

Board is the personal research workspace, on the same research tray SIFT 2.0 uses (`src/state/tray.tsx`: one device-local store, no account, no new storage). It answers three questions: what have I saved, what has changed since, and what deserves another look. Reused: `boardGroups`, `gameChanges` (`src/board/model.ts`), `matchSignal`/`standingOf` (Signals), `useAllOpportunities`, the live quote store and its freshness rule, `ResearchSheet`. New code: `src/v4/Board.tsx` and the pure `src/v4/boardModel.ts`.

- **Saved**: by game (soonest first), then by category (game thesis, players, props, markets, scripts, findings, other). Each row shows the contract, the side (YES/NO pill) and when it was saved; the item sheet adds the original context, your note, and the saved quote's time. Sport and type filters are in the address.
- **What changed**: the saved price against the latest quote of the SAME contract and the SAVED side (a NO save compares the NO ask). A quote counts only if it is FRESH or AGING and the contract is open; a stale or undated quote is shown as context ("not compared"), a missing quote, a closed contract and a save with no price are each said in words. A move is a move: the Board never says a lower or higher ask is a profit. Game changes (started, final, postponed) and "the publication has a newer research run" come from the classic Board's own rules; pregame research is marked frozen once the game starts.
- **Worth another look**: only evidence: a move of 5 cents or more on the saved side, a postponed or cancelled game, a newer research run, a published signal (or a pass) on the exact saved contract and side. Each is worded neutrally and says nothing about acting.
- **Open**: a saved NFL prop opens the player on the saved side (`?stat=&side=under`); a saved market opens Signals on that contract and side when the publication has a signal, else the game's markets; a game opens the game; a player opens the game's players. Items with no v4 screen (a team, a metric, a ranking …) open the SIFT 2.0 page they were saved from, as a real mode exit.
- **Remove / clear**: each item has a remove control; "Clear Board" opens a confirmation that says the Board is shared with SIFT 2.0 on this device.
- **Compatibility**: item ids and timestamps are never rewritten. A save made before sides were recorded has no side and has always meant YES (the item sheet says so); a NO save is a different item with its own identity. Opening the Board changes nothing in storage.
- **Missing information**: a game that is no longer on the publication's board, and a game whose publication could not be read, each say so on the game card, with no change claimed. If no publication can be read at all, the saved items are still listed and the Board says nothing changed is unknown.

## What is real, and what is not

| Element | Source | State |
| --- | --- | --- |
| Games, start times, lifecycle (upcoming / in play / awaiting result / final / postponed) | Published boards via `useAllOpportunities` / `gameRows` | Real |
| Final scores | `extensions.result` of the game's research document | Real, only when the publication reports both numbers |
| Live score, clock, period, down and distance, plays | **Not in the published contract** | Unavailable: said so on the card, the row and the Live tab; nothing is estimated. **Opt-in exception:** *Live scores* (early access, off by default, per device) reads real NBA scores, and finished tennis matches, from SportScore's free API, matched to the published game by both teams, orientation and start time, with their age and the "Powered by SportScore" credit ([LIVE_SCORES_REAL.md](LIVE_SCORES_REAL.md)). NFL, college football and NHL stay unavailable (no free feed whose terms permit this). Scores never touch research, prices, projections, signals or the Board |
| Team logos, venue photograph, team colours | Hero system (`resolveHero`), verified venue tiers, committed logos | Real; branded graphic when no verified photo exists |
| Player photos | `broadcastPlayerPhoto` (identity-checked, reviewed) | Real; team crest when none is approved |
| Records | Verified league schedule (NFL) | Real where available |
| Matchup edges, game scripts | Existing NFL insight layer (`matchupInsights`, `gameScripts`) | Real for NFL; other sports say they are not published |
| Player projections | `propCards` with the projection-authority layer (one projection per metric) | Real for sports with projections; shown beside, never merged with, the Kalshi line |
| Kalshi markets, asks, freshness | Publication markets overlaid with live quotes (`overlayMarket`) | Real; quotes older than 30 min are marked stale, capture times shown |
| Research signals | Published opportunities (`Opportunity` contract) | Real; pregame research is labelled frozen once a game starts |
| Following | Local list in `localStorage` (`sift.v4.follow`) | Device-only |

v4 never says "bet": the sheet names what the publication states (its side, price, fair range, fee-aware break-even, its
own upper limit price) and says it is research only.

## Reviewing it

```
npm ci
npm run dev
# open http://localhost:5173/sift-sports-intelligence/#/v4   (check the printed URL)
```

Resize to 390 x 844, 375 x 812 and 375 x 667 (or use device mode). Use `#/v4/game/nfl/<event id>` for a game; every game
row on Home and Games links there.

### On an iPhone (from a MacBook Pro, same Wi-Fi)

This serves the real production bundle from your Mac. Nothing is hosted.

1. Put the Mac and the iPhone on the **same Wi-Fi network**. Avoid guest networks ("client isolation" blocks it) and turn
   off any VPN on either device.
2. On the Mac, in this repository: `git checkout feat/v4-app-foundation && npm ci`.
3. Run `npm run preview:lan`. It builds into `dist-lan` (about a minute) and serves it on `0.0.0.0:4173`. If macOS asks
   whether `node` may accept incoming connections, choose **Allow**. Use `-- --port 4200` for another port and
   `-- --skip-build` to reuse the last build.
4. The terminal prints the exact address, for example `http://192.168.1.23:4173/sift-sports-intelligence/#/v4`. If it
   prints several, use the one on your Wi-Fi (usually `192.168.x.x` or `10.x.x.x`). On a MacBook Pro the Wi-Fi address is
   also `ipconfig getifaddr en0`.
5. On the iPhone, open **Safari** and type that address. If iOS asks to let Safari find devices on the local network,
   allow it. Use the IP address, not a `.local` name (Vite may reject host names).
6. Stop the server with Ctrl+C.

For hot reload while developing, `npm run dev:lan` serves the dev build the same way (port 5173); it is not representative
for performance.

If the page does not load: confirm the phone is on the same Wi-Fi, open the same address in the Mac's own browser, check
the macOS firewall prompt and VPNs. Safari's Web Inspector (iPhone Settings > Safari > Advanced > Web Inspector, then the
Mac's Safari Develop menu over USB) gives console and timeline access.

**Still pending, not yet performed:** real iPhone Safari verification, VoiceOver, and on-device performance. Suggested
pass: Home with a full slate (scroll, league and date strips, Following sheet), Games, a game's four tabs, the research
sheet, rotation, safe areas (home indicator, notch), VoiceOver through the tab bar, tabs and sheet, and a Safari
timeline of scrolling Home.

### WebKit Playwright

The `iphone` and `iphone-se` projects need Playwright's WebKit build. In the cloud environment this work was done in, the
download host (`playwright.download.prss.microsoft.com`) is blocked by the network policy (403), so those projects could not
be run here and no result is claimed. On the Mac:

```
npx playwright install webkit
npm run build:e2e
npx playwright test e2e/v4.spec.ts --project=iphone --project=iphone-se
```

The projects and gates are unchanged (`iphone` runs the `@smoke|@journey|@live|@visual` tests, `iphone-se` the `@smoke`
ones); the v4 spec's tests are tagged `@smoke` where they should run on both.
