# D. SIFT Asset Library Specification

Status: **proposal for owner approval, 2026-10-18.** Nothing is implemented. Conventions: [V] verified in the repository, [R] recommendation, [U] unverified.

Design constraints taken from the audit (document A) so this spec fits what exists rather than duplicating it:

* Photographs, logos and player images already have working, tested pipelines with manifests (`scripts/heroes/pins.json → photos.json`, `scripts/teams/*`, `scripts/players/*`). **The library does not replace them; it registers them and adds the asset classes SIFT lacks.** [V]
* `scripts/heroes/fetch.mjs:77-81` deletes any file under `public/heroes/*` that no pin owns, so **new classes must not live under `public/heroes/`**. [V]
* WebP is the shipped format; `HeroArt` loads via `fetch()` into a blob (`src/lib/useImage.ts`), not `<picture>`, with `HubMast` and `Hero.tsx:221` as the two `srcSet` exceptions. [V]
* The SIFT 2.0 art-direction layer (`venueArt.ts`, `heroArt.ts`) already adds per-surface focus points and quality verdicts on top of the resolver. [V] The library generalises that pattern.

---

## 1. Why not the illustrative tree

The brief's example (`athletes/nfl/…`, `teams/`, `stadiums/`, `compositions/desktop|mobile/`) is a sensible default, but against this repo:

| Illustrative folder | Verdict | Reason |
|---|---|---|
| `athletes/<sport>/` | **Dropped as a generated class** | Policy forbids generated athletes (A §7.7). Existing authentic photos stay in `public/players/` under their own pipeline and blocklist |
| `teams/` | **Not duplicated** | `public/teams/<sport>/` and the `*-logos.json` manifests already exist |
| `stadiums/` | **Not duplicated** | Existing `public/heroes/<sport>/` (+ `public/sift2/venues/`) is the venue store; stage plates are explicitly *not venues* |
| `compositions/desktop|mobile/` | **Replaced** | Compositions are assembled at runtime from layers (B §2). Desktop and phone are *variants of one asset*, not separate compositions, so there is no duplication |
| `backgrounds/`, `effects/`, `icons/`, `sports/`, `intelligence/`, `research/` | **Kept, regrouped** into asset *classes* below | |

## 3. Naming conventions

Immutable, lowercase, hyphenated. One ID per concept; variants are suffixes.

```
<class>.<scope>.<subject>.<descriptor>.v<N>
env.nfl.night-turf.signature.v1
fx.all.floodlight-cones.cold.v1
obj.basketball.hero-3q.v1
intel.all.signal-field.masthead.v1
state.board.empty.v1
brand.all.splash-portrait.v1
```

* `class`: `env | fx | obj | intel | state | brand | glyph` (new), and `venue | player | team` (existing, registered read-only).
* `scope`: a sport slug from `src/data/sports.ts` (`nfl`, `cfb`, `nba`, `cbb`, `nhl`, `mlb`, `soccer`, `tennis`) or `all`.
* **Files:** `<id>.<form>.<width>.<ext>` where `form` is `d` (desktop wide), `m` (phone tall), `c` (card) or `o` (object), e.g. `env.nfl.night-turf.signature.v1.d.1920.webp`. For cache-safety the delivered filename embeds the first 8 hex of the content hash (`…d.1920.3fa9c21b.webp`), so assets are immutable and never need invalidation.
* **Versions:** a changed asset gets a new `vN`; the old file is deprecated, not edited. Existing IDs in `photos.json` are kept as they are.
* Banned in names: team names, athlete names (nothing in the new classes is team- or person-specific by construction; team colour comes from CSS).

## 4. Metadata: the sidecar (`meta.json`, schema `sift.asset/1`)

Every shipped asset, new or registered, has one. Fields marked ★ are required for publish.

```jsonc
{
  "schema": "sift.asset/1",
  "id": "env.nfl.night-turf.signature.v1",              // ★
  "class": "env", "scope": "nfl",                        // ★
  "purpose": "Stage plate beneath Command Center and Games hero when no verified photo exists",
  "surfaces": ["command-hero", "games-hero", "home-hero", "props-masthead"],   // ★ from a closed list
  "contains": { "people": false, "text": false, "logos": false, "real_venue": false },   // ★ asserted, then machine-checked
  "producer": {                                          // ★
    "kind": "diffusion",                                 // diffusion | blender | procedural | photo | vector
    "tool": "ComfyUI", "tool_version": "…", "workflow": "workflows/comfy/env-wide.api.json",
    "model": "FLUX.1-schnell", "model_license": "Apache-2.0", "model_card_sha256": "…",
    "prompt": "…", "negative": "…", "seed": 482913, "steps": 4, "sampler": "…", "size": "1536x512",
    "generated_at": "2026-10-20T03:12:00Z", "operator": "…"
  },
  "human_authorship": "Selected from 6 candidates; graded and composited with team-light layer; effect arrangement by operator",
  "variants": [                                          // ★ §5
    {"form": "d", "w": 1920, "h": 640, "file": "…webp", "bytes": 118000, "focus": {"desktop": "50% 55%"}},
    {"form": "d", "w": 1200, "h": 400, "file": "…webp", "bytes": 64000},
    {"form": "m", "w": 780,  "h": 975, "file": "…webp", "bytes": 91000, "focus": {"mobile": "50% 30%"}},
    {"form": "c", "w": 720,  "h": 360, "file": "…webp", "bytes": 34000}
  ],
  "tone": "night",                                       // night | indoor | daylight | neutral (as venueArt.ts)
  "text_channel": {"desktop": "36%x60% centre-bottom", "mobile": "bottom 55%"},
  "palette": {"dominant": ["#07111f", "#12304f"], "lum_text_channel_mean": 0.045},
  "qc": {                                                // ★ machine results, §7
    "faces": 0, "ocr_hits": 0, "text_channel_p95_lum": 0.11, "blur_var": 420, "banding": "pass", "palette_delta_e": 6.2
  },
  "license": {                                           // ★
    "spdx_or_terms": "asset-original (see LICENSE-ASSETS.md)", "attribution_required": false,
    "share_alike": false, "third_party_inputs": []       // every input listed, with its own licence
  },
  "approval": {"file": "approvals/env.nfl.night-turf.signature.v1.json"},   // ★ for publish
  "status": "published", "supersedes": null, "created": "2026-10-20"
}
```

For **photographs** (registered, not generated) the same sidecar carries the existing fields: `source` (Commons URL), `file`, `artist`, `license`, `licenseUrl`, `modifications`, `identity`, `from/to` era, the pin's dated `review`. These already exist in `photos.json` / `player-images.json`; the registry view maps them in. A `third_party_inputs` entry is **mandatory** if any photograph was used as an input to a plate (not recommended, B §2 rule 1).

## 5. Responsive variants

Derived from the measured geometry in A §3. Two masters, never stretched; a card crop for rows and tiles.

| Form | Master | Delivered widths | Display slots | Notes |
|---|---|---|---|---|
| `d` desktop wide | 3 : 1, 2400 × 800 (PNG/EXR, in `masters/`) | 1920, 1200 | Command hero 2.7 : 1 (454 px), Games hero 2.5 : 1 (502 px), Home hero, masthead; ≥1800 px at 550 px | One focus string `--focus-d`; text channel centre 36 % × lower 60 % |
| `m` phone tall | 4 : 5, 1080 × 1350 | 780, 540 | Command 1.56 : 1 (250 px) and 1.93 : 1 (202 px Props tab), Games 0.9 : 1 (405 px), Home phone | One focus string `--focus-m`; top 44 px and bottom 56 px kept clear; energy in the top 45 % |
| `c` card | 2 : 1, derived by crop with focus | 720 | Game rows, tiles, intelligence detail | ≤ 40 KB |
| `o` object | square or 4 : 3, with alpha, from Blender | 800, 400 | Prop-card art, unit art, empty states | Transparent, no baked shadow beyond the object |

* **Decision per component** (the brief's "separate assets, responsive cropping, dynamically assembled, or reusable overlays"):
  * Command, Games and Home heroes: **separate desktop and phone masters** (different compositions), plus **dynamically assembled** team light and effects.
  * Rows, tiles, cards: **responsive crop** of the card variant.
  * Prop and driver cards: **reusable object + dynamic team colour**.
  * Mastheads on Intelligence, Lab, Board: reuse the desktop master with a phone master for the same ID.
  * Brand: fixed files.
* **Selection** reuses `venueImageSource` (`src/components/sift2/heroArt.ts:25-29`): measure the container width, cap DPR at 2, tolerate a 2.5 % upscale, pick the smallest sufficient file. Extend to plates; no new algorithm.
* **Format** [R]: WebP only at first, matching the shipped pipeline, `useHeldImage`, and ImageMagick quality settings (`fetch.mjs:62-63`, q60-66, `method=6`). AVIF is an optional second step: sharp can emit it [V], but `<picture>` is not how heroes load today and WebP/AVIF are not in the SW precache (`vite.config.ts:67`). Evaluate AVIF only if the budget is missed.
* **Focus:** every `d` and `m` variant carries a focus string, as `VENUE_ART` does (`50% 59%` / `58% 63%`).

## 7. Quality gate: measurable acceptance criteria

Applied to every asset before approval. **Auto** = computed by `saf check`; **Human** = reviewer ticks a box in the approval file. Numeric thresholds marked ◇ are starting values to be **calibrated in the spike (C §9)** against 20 hand-picked approved references, not assumed.

### 7.1 Authenticity

| ID | Criterion | Applies to | Method | Threshold |
|---|---|---|---|---|
| AU1 | Athlete correct (face and name match the published player) | photos (tier A) | Human, against `players.json` identity and the pin's `review` | 100 % |
| AU2 | Uniform correct (current team kit, era) | photos | Human; existing rule: game-day frame only; blocklist for college, former-team, press, camp, charity (`player-image-blocklist.json`) | 0 blocklist hits |
| AU3 | Jersey number legible and correct, or not shown | photos | Human | legible and correct, or crop excludes it |
| AU4 | Team identity correct for the surface | photos, venues | Existing `heroRegistry` tests (team is a tenant of the venue in that era) | pass |
| AU5 | No generated person, face, hand, jersey, number or mark | plates, objects | **Auto** face detection + OCR | faces = 0; OCR hits = 0 |
| AU6 | No fake logos or league marks | all new classes | Auto OCR + Human | none; no league/brand mark on equipment |
| AU7 | No distorted anatomy or equipment | photos | Human | none; AI-"enhanced" or upscaled faces rejected outright |
| AU8 | Not a real venue unless a verified photo | plates | Human + metadata `contains.real_venue = false` | false |

### 7.2 Composition

| ID | Criterion | Method | Threshold |
|---|---|---|---|
| CO1 | Text channel dark: centre 36 % × lower 60 % (desktop), lower 55 % (phone) | Auto (sharp stats on the master; re-measured on the rendered component, see IN1) | mean relative luminance ≤ 0.06 ◇, p95 ≤ 0.12 ◇ |
| CO2 | Survives every target crop: 2.7 : 1, 2.5 : 1, 1.56 : 1, 1.93 : 1, 0.9 : 1, ≥1800 px | Auto-render each crop; Human check | focal energy zone inside every crop |
| CO3 | Safe margins respected | Auto (zone masks) | nothing but background in top 44 px and bottom 56 px on phone; top 12 % on desktop |
| CO4 | Intentional negative space | Human | centre channel visibly darker than both edges |
| CO5 | Desktop and phone are separate compositions, not a crop of each other | Human | phone master has its own sketch/seed |
| CO6 | Professional cropping, no clipped subject, no horizon tilt | Human | pass |
| CO7 | Visual hierarchy: art never outranks the matchup text or numbers | Human, on the rendered component | pass |

### 7.3 Visual quality

| ID | Criterion | Method | Threshold |
|---|---|---|---|
| VQ1 | Sharp where intended; no soft upscale | Auto (Laplacian variance on the master) | ≥ ◇ value from references; no upscaled master |
| VQ2 | Lighting reads as one coherent key + rim | Human | pass |
| VQ3 | No banding in gradients | Auto (histogram gaps) with grain at 8-bit | pass; grain ≥ ◇ |
| VQ4 | Palette within SIFT range | Auto: dominant colours vs the neutral cool range | CIEDE2000 ≤ 12 ◇ |
| VQ5 | No tiling / repeated texture / melted geometry | Auto autocorrelation + Human | pass |
| VQ6 | Cohesive grade across the library | Human, on a contact sheet of all plates | pass |
| VQ7 | Natural textures; no obvious AI artefacts | Human | pass |
| VQ8 | SIFT identity: cold key, team-colour rim, no neon | Human | pass |

### 7.4 Application integration (measured on the real component with Playwright, desktop 1352 × 454 and phone 390 × 250 / 390 × 405)

| ID | Criterion | Threshold |
|---|---|---|
| IN1 | Text contrast over the rendered background, every text element | ≥ 4.5 : 1 for text < 24 px or < 700 weight; ≥ 3 : 1 for ≥ 24 px bold (WCAG 2.x); p95 over the element's box |
| IN2 | Responsive behaviour | no horizontal overflow at 320, 390, 720, 1024, 1250, 1536, 1800; focus point visible at each |
| IN3 | Loading | art never blocks first paint (CSS layers paint first); LCP delta ≤ 100 ms ◇; CLS = 0 |
| IN4 | Accessibility | art `aria-hidden`/`alt=""`, identity in text; axe passes; `prefers-reduced-motion` respected; credit chip ≥ 11 px and ≥ 4.5 : 1 |
| IN5 | File size | within §6 |
| IN6 | Graceful fallback | missing, 404 or corrupt file → branded wash, no layout change (the existing corrupt-bytes test pattern, `e2e/sift2-fidelity-capture.spec.ts:52-69`) |
| IN7 | Cross-browser | Chromium desktop + phone, WebKit iPhone and iPhone SE pass the existing matrix |
| IN8 | Visual regression | baselines updated via the existing `[update-visual-baselines]` workflow, reviewed by a person |

A candidate that fails any *Auto* row is rejected before a human sees it. A candidate passes only if every *Human* row is ticked by a named person.

## 8. Licensing records

| Rule | Detail |
|---|---|
| **Allowed licences for shipped assets** | Original work of the owner (class `asset-original`); CC0 / public domain; CC BY; CC BY-SA (existing photographs, with share-alike handling below); Apache-2.0 / MIT-licensed components (flag set, fonts). **Not allowed:** NC, ND, unknown, "free for personal use", AI outputs from a model whose licence forbids commercial use or is unread |
| **Per-asset record** | The sidecar `license` block lists every third-party input with its own licence, URL and the exact modification. For generated assets: model, model licence, model card hash, prompt, seed |
| **Share-alike** | New classes contain no BY-SA input (B §2 rule 1), so the new art is unencumbered. Existing BY-SA photographs remain BY-SA; the repository should carry a `NOTICE` for `public/heroes`, `public/players`, `public/sift2/venues` (none exists today, A §7.2). [R] |
| **Attribution UI** | Extend the existing credits table (`Status.tsx:89-104`) to iterate the unified registry, so every photograph, including the Arrowhead frame, is listed. On-image credits show the full artist and a licence link; the on-image chip becomes ≥ 11 px (today 9 px / 7 px, truncated at 32-40 chars). Generated art needs a one-line "Original SIFT artwork" entry, not an AI disclaimer, unless the owner wants one |
| **Third-party marks** | No new asset may contain a league, team, brand or sponsor mark. Logos remain under the existing logo manifests, whose provenance gap (A §7.1) is an owner item |
| **Re-check** | Photograph licences are verified at fetch time only (`fetch.mjs:16`, A §7.8). Add a scheduled (monthly) CPU-only job that re-reads Commons `extmetadata` for every registered photo and opens an issue on any change. [R] |
| **Likeness** | A manifest field `likeness: cleared | pending | none` per player photo, with a per-sport kill-switch in the registry. Default `pending` (A §7.5). A sport's player photos can be hidden without a deploy of new art |

## 9. Version control, storage and reproducibility

* **Git** holds manifests, templates, workflows, sidecars, approvals and the delivered outputs (WebP/SVG). These are small and reviewable.
* **Masters and EXR/PNG** are large. Options: Git LFS (free quota is limited [U: verify current GitHub LFS free storage and bandwidth]), or GitHub **release assets** per library version, or keep them on the owner's disk with a recorded checksum. [R] Release assets: free, versioned, outside the Pages deploy.
* **Pages budget:** the live site is hosted on GitHub Pages and already ships 129 MB under `public/` [V: `du`]. [U] Pages has size guidance (≈1 GB soft site limit); the new art adds ≈ 15-25 MB. Verify before the first large batch.
* **Reproducibility:** seed + workflow JSON + model hash + tool versions re-create a candidate; Blender/procedural assets re-render from scripts.
* **Immutability:** content-hashed filenames; a changed asset is a new `vN`.
* **Branching:** artwork PRs touch `public/art/**`, `src/lib/art/**`, `assets/**`, `approvals/**` only; reviewers see before/after on the real component.

## 10. Approval workflow

```
requested ─► candidate ─► auto-checked ─► in review ─► approved ─► published ─► deprecated
   │            │              │              │            │
   │            └─ reject (faces/OCR/luminance/budget fail, automatic)
   └────────── manifest/assets.yml entry created by a person; `saf plan` lists it as MISSING
                              in review ─► rejected (reason recorded; seed and prompt kept)
```

* Roles: **owner/approver** (a named person: the only one who can run `saf approve`), **operator** (runs generation, may be the same person).
* The approval file records: approver, date, the checklist (every Human row of §7), the SHA-256 of each shipped file, and an optional note.
* `published` means present in `registry.json`; CI enforces §7 and the approval hash.
* `deprecated` assets stay on disk until no registry entry references them; a test checks for orphans in both directions.

## 11. Integration with SIFT (no layout change)

1. **Registry, not hard-coding.** `src/lib/art/registry.json` (generated). A small pure resolver (style of `src/lib/hero/resolve.ts`) returns a plate for `(sport, surface, form, tone)`; it never decides identity. `resolveHero` stays authoritative.
2. **Fallback chain** (graceful, ordered): verified photograph → stage plate → branded wash (existing `HeroArt`) → canvas colour. Each step is independent; a missing file at any step drops to the next with no layout change.
3. **Hook point:** `VenueArt` already renders the branded layer first and the photo on top; add the plate between them. `broadcastHeroSpec` (`heroArt.ts:10-17`) is the existing seam for art direction.
4. **Tests to add** (modelled on existing ones): registry ↔ files exist; every entry has licence, sidecar, approval hash; no entry under `public/heroes/`; classes with `contains.people=true` rejected for `env`/`obj`; budgets; plates never selected for a `photo`-kind spec above the 25 % opacity rule; corrupt plate falls back (extend `sift2-fidelity-capture.spec.ts`); extend `tests/sift2ArtDirection.test.ts` for plate focus.
5. **Service worker:** add a runtime CacheFirst rule for `/art/` (the current rule matches only `/heroes/`, `vite.config.ts:91-100`) with an entry cap.
6. **Visual baselines:** art changes pixels in baselines under `e2e/__screenshots__/`; refresh through the existing `[update-visual-baselines]` workflow after human review.
