# SIFT 3.0 screen build guide (read before touching a screen)

The approved research designs are LOCKED. Implement them; do not redesign, reinterpret or "improve" a layout. If a locked design cannot be met with published data, build the honest locked/absent state the design system defines and say so in your report. This guide is the contract between the foundations (already built) and each screen.

## Sources of truth (all in `docs/sift3/redesign/`)
- `DESIGN_SYSTEM.md`: palette, the three evidence lanes (Market square periwinkle, History ring ivory, SIFT model diamond cyan: never blended, never subtracted into an "edge"/"value"), tilt rule (|gap| <= 15 is Even), universal navigation table, prices and freshness, sports and extensibility, hockey records, game times, statistic screens.
- The mockups: `out/<id>.png` (clean) and `out/<id>-annot.png` (data-status overlay: BUILT / WIRE / NEW). The code that drew them: `mock.js`/`mock.css`/`theme-b.css` (Player and Game), `pd.js`/`pd.css` (Prop Discovery), `tr.js`/`tr.css` (Team), `sd.js`/`sd.css` (Stat), and the interactive `proto-*.js` + `walkthrough.html`. `theme-b.css` overrides the navy colours in the other CSS files: the ink/graphite values win. Spacing, type sizes, radii and chart geometry in those files ARE the spec.
- `board-*.html` explain each state. `docs/sift3/BACKEND_BACKLOG.md` lists data that is not published (locked rows).
- The 78 tap targets: `tests/v3/tapmatrix.ts` (data) and `docs/sift3/redesign/walk.test.mjs` (the original assertions). Your screen's rows must pass against the REAL components, and Back must restore the screen's exact state and scroll after each.

## What already exists (use it; do not rebuild)
- State in the address: `src/v3/state/url.ts` (`useRouteState(schema)`, `useQueryPatch`), vocabulary in `src/v3/nav/schemas.ts`. In-place changes (tab, window, line, filter, sort, selection) REPLACE history; only sheets and real navigation push. Add fields to your screen's schema (adding is not a version change); renaming one needs a migration. Never hand-build a query string.
- Navigation: `src/v3/nav/Targets.tsx` (`TeamLink`, `PlayerLink`, `StatLink`, `GameLink`, `PropsLink`, `PriceTap`, `NavRow`) and `routes.ts`. Every identity, number and object is a target with ONE meaning everywhere; 44 pt hit areas; never nest an anchor in an anchor (use `NavRow`'s stretched link with raised targets). Every target must carry `data-tap`/`data-dest` (the components do).
- Sheets: `src/v3/ui/Sheet.tsx` (`useSheet().open(...)`, `registerSheet` for addressed sheets like `?sheet=contract&tk=`). A state change made inside a sheet lands on the screen underneath after the sheet closes (automatic when you use `useRouteState`/`useQueryPatch`).
- Scroll: handled in the shell; never call `window.scrollTo` for state changes.
- Atoms: `src/v3/ui/atoms.tsx` (+ `atoms.css`): `Lanes`, `LaneTrack`, `PercentileTrack`, `Tabs`, `Seg`, `LockedRow`, chips, pills. Add your screen-specific chart atoms in new files under `src/v3/ui/charts/`.
- Data layer: `src/v3/data/research/` (`useTeamProfile`, `useRankingCatalog`, `useRankingDoc`, `useSchedule`, `useTeamIndex`, `useMetricDefs`, `deriveRelated`, `teamRecord`, `percentileOf`). Real published documents only. One team profile gives every statistic, window, rank, universe size and ranking id; fetch a ranking document only when a statistic is opened. Older hooks (`useStat`, `useTeam`, `usePlayer`, `useGameExtras`, `useSlate`) still work and may be used for game logs, markets and the slate.
- Capabilities: `src/v3/model/capabilities.ts`: render a section only if `isReady(slug, section)`; otherwise absent or a `LockedRow` with `lockedReason(...)`. Never hard-code a sport or the current slate into behaviour; a new sport must be a declaration, not a screen change.
- Prices: ONLY through `src/v3/data/quoteGate.ts` (`gate`/`usablePrice` with a `QuoteContext`). A withheld price is "—" in a list; in the exact-contract sheet it is "Price unavailable right now" with Retry, and the fee and break-even rows are hidden. NO freshness UI anywhere: no ages, "ago", "last known", timestamps, stale badges (existing `ago()`/`quoteState()` text must not appear in anything you build).
- Saved research: `src/v3/model/saved.ts` + `state/prefs.ts` (`saveResearch({title, subtitle, route, chips, snapshot})`). The saved route is the screen's address with its full state; opening it must restore that state exactly.

## Honesty rules
- Never invent a number, a probability, a recommendation or a value signal. Missing data is "—" or a locked row naming the reason. The SIFT model lane shows only values from the approved model publication gated by the approval ledger (look at how `src/` reads projections/ledger); otherwise "—" with "not approved yet". History is observed frequency (hits over the shown window, e.g. 4 of 10). Market is the pre-fee Kalshi ask.
- Distinguish real from sample: `?demo=1` shows the app's labelled sample data (existing behaviour); real mode must work on real published documents. A section with no sample data in demo mode may be absent in demo, but never silently substituted in real mode.
- Do not change production routes, workflows, model activation, ledgers, `src/live`, `relay/`, v4 or SIFT 2.0.

## Quality gates (run before you report)
1. `npx tsc -b`, `npx eslint src/v3 tests/v3 e2e`, `npx vitest run tests/v3` all clean.
2. Unit tests for every new pure function and view-model (real fixtures in `tests/v3/fixtures`, trimmed copies of real documents; add more by trimming real ones, never fabricating).
3. Playwright (dev server) spec `e2e/v3-<screen>.spec.ts`: `npx playwright test -c playwright.v3.config.ts e2e/v3-<screen>.spec.ts` (`V3_PROJECTS=v3-phone`). It must (a) exercise every tap-matrix row owned by your screen against the real components using real published documents (`import { useRealFeeds } from './support/realFeeds'`; `V3_REAL_FEEDS=live` fills the cache through the proxy) and check each destination via `data-dest`/URL, (b) assert Back restores the screen's state (tab, window, line, filters, sort, selection, expanded rows) and scroll offset, sheets closed, (c) assert no horizontal overflow at 390 and 375 px, and that no freshness text exists.
4. Visual parity: take phone screenshots with `REAL=1 V3_REAL_FEEDS=live node --experimental-strip-types scripts/v3-qa/shot.mjs OUT_DIR "/v3/..."` (set `FULL=1` for full page) and compare against the locked `out/*.png` for each state your screen owns (geometry, density, colour, type, chart treatment). Fix differences; list any remaining difference honestly. Save your comparison images under `docs/sift3/qa/impl/<screen>/` (reference left, implementation right).
5. WebKit: the WebKitGTK driver is installed (`scripts/v3-qa/start_driver.sh &`, then `python3 scripts/v3-qa/journeys.py` for the shared journeys; write a small selenium check like `scripts/v3-qa/wk.py` for your screen's critical paths: Back state, sheet close, scroll). Playwright's own WebKit cannot be downloaded in this sandbox.
6. Existing `e2e/v3.spec.ts`, `e2e/v3-foundations.spec.ts` and `scripts/v3-qa/journeys.py` keep passing (update an assertion only where the locked design intentionally changed the behaviour, and say so).

- Touch shared files minimally: `src/v3/nav/schemas.ts` (add fields to YOUR schema only), `src/v3/model/capabilities.ts` (only to correct a declaration, with the evidence), `src/v3/v3.css` (avoid; use your own css file imported by your screen or by `V3Root.tsx` with one added line). Another worker is editing other screens in parallel; keep your edits to your screen's files plus new files. Do not open a pull request.
- If the dev server is needed: `npx vite --port <your port> --strictPort &` (use a port other than 5173; set `V3_PORT`/`BASE` accordingly). Chromium: set `SIFT_CHROMIUM=/opt/pw-browsers/chromium-1243/chrome-linux64/chrome` if auto-detect fails. The shared `node_modules` may need `npm ci` in your worktree.
- Report: what is implemented; which locked states are functional; which real documents feed it; test results (counts); visual comparison findings; anything unverified, stubbed, locked or needing the owner's decision. Be factual: if something does not work, say so.
