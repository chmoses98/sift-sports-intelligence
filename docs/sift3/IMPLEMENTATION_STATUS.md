# SIFT 3.0 implementation status

Branch `claude/sift3-impl`, stacked on `claude/sift3-build` (PR #147, draft). Everything is behind the single `#/v3` opt-in. Order (approved 2026-10-26): 0 Foundations, 1 Data layer, 2 Stat Detail and League Rankings, 3 Player Research, 4 Team Research, 5 Game Detail and Matchup, 6 Prop Discovery, 7 Saved research and shell, 8 Hardening. Quote engineering runs on its own branch (`claude/quote-track`, see `docs/quote-track/README.md` there).

## Milestone 0: Foundations (done)

**Contracts now in code**

| Contract | Where | What it guarantees |
| --- | --- | --- |
| Versioned URL state | `src/v3/state/url.ts`, `src/v3/nav/schemas.ts` | One schema per screen (player, team, stat, game, props). Decoding never throws and falls back per field; encoding omits defaults and is deterministic; `v=1` is written whenever a field is. Parameters without `v` are version 0 and migrate forward (`?tab=rankings&team=DAL` becomes `ranking`, `sel=DAL`). Unknown and shell parameters pass through. |
| In-place changes never add history | `useRouteState`, `useQueryPatch` | Tab, window, line, filter, sort and typed text replace the entry; Back therefore leaves the screen, and the entry below keeps its own state. Several updates in one handler compose. |

| Scroll memory | `src/v3/state/scroll.ts` | Per history entry; committed on arrival before anything scrolls; in-place changes never move the page; a new screen starts at the top; reload falls back to the address; shell parameters are not part of the page key. |

## Milestone 6: Prop Discovery (PD1 to PD6)

Branch `claude/sift3-m6-props`. Route `/v3/props` (lazy; Prop Discovery owns the address, it is never handed to the classic `/:slug/props` route). One address holds the home (`view` absent), the list (`view=list`, implied by any list field) and the comparison (`view=compare`); sort, filters, search text, selections, compare mode, the expanded row (`exp=id` or `id@k` for another rung) and `pin` are all in it, in place changes replace history, typed text never adds an entry per keystroke.

**Explore tab decision.** The Explore tab is rooted at Prop Discovery (the locked walkthrough's `E.nav` roots Explore at the Prop Discovery home). The older search screen stays at `/v3/explore` under the same tab and keeps working (the Home and Games search icons, Following's "find teams and players" and the stat search journey all open it); the PD home search field searches props only. Tab lighting: Games for Team, Player and Game; Explore for Stat Detail, Prop Discovery and the older search.

**Universe (cost bound).** There is no all-games prop manifest, so the universe is a join of published documents read lazily and shared with the rest of the app: per game `event_detail` (the contract ladders; 0.3 to 1.3 MB each), the sport's explorer index (roster to team, which players have a profile), the NFL history index, event research for injuries where the game's own document carries none, the projection feed only for sports with an approved model, and one ranking document per opponent unit. A game enters the universe when it is real, pre-game, in a sport `capabilities.ts` marks `propPrices: ready`, starts within 48 hours (`PROP_HORIZON_MS`) and its board row says at least one market is listed. This is what keeps a 300-game college slate (0 player markets today) from costing 600 documents. No player log is read up front: History is computed for rows on screen (after the viewer pauses), the expanded row and card shelves, from the NFL history file (about 7 KB per player) or the NHL player profile's game log (about 28 KB).

**Default sort.** The design's default is History hit rate; ranking 335 or 1000 rows by it needs every player's log and no bulk published summary exists. The default is therefore Soonest (needs no log). Sorting or filtering by History loads logs only on request: up to 30 missing logs load automatically, beyond that the list says "Load history for N more players (about X KB)" and ranks only rows whose log is loaded, saying so. A row without a loaded log never ranks above one that has it and never passes a History threshold; nothing is faked.

**Lanes.** Market is the gated pre-fee ask; History is hits over the last 10 games from the player's log; SIFT model is shown only where the approval ledger approves the family AND the published projection passes its checks (`lib/projectionApprovals.ts`, `lib/projectionAuthority.ts` through `data/props/model.ts`): today NFL receptions and completions and MLB pitcher outs and strikeouts. Everything else is "—" with the reason ("not approved yet"; NHL skaters are under validation). The lane is never blended, subtracted or sorted against Market; no "edge" or "value" wording exists.

**Prices.** Only through `data/quoteGate.ts` (list context for rows, contract context in the exact-contract sheet). A withheld price is "—" in rows, cards, rung chips and compare; the sheet shows "Price unavailable right now" with Retry and hides ask, bid, implied, fee and break-even. Rows register their tickers at the `game` cadence only after they have stayed on screen for 450 ms; opening a row asks once for its whole ladder (`refreshNow`). Seam for `claude/quote-track`: `usePropPrices` (`addRowsScope`) and the open-row refresh (`refreshContract`). With the current feed (3.5 minutes plus a 5-minute CDN cache behind, and no NBA/CFB/CBB games in it) most list prices are withheld by the approved age rule until the relay carries them: that is the rule working, not a defect.

**Real-document tests.** `e2e/v3-props.spec.ts` (23 tests) runs on the cached real documents under a fixed browser clock (`feedNow()` in `e2e/support/realFeeds.ts`, written to `.v3-feed-cache/captured_at.txt`; real-document caches describe one instant) and `freshQuotes()` re-stamps only the quote feed's observation times (a test transformation; prices untouched) or makes the feed fail for the missing-price states. Unit tests: `tests/v3/props-data.test.ts` (24) and `tests/v3/props-universe.test.ts` (12). WebKit: `scripts/v3-qa/props_wk.py` (48 checks at 390x844 and 375x667) and `journeys.py` (48). Performance probe: `scripts/v3-qa/props-perf.mjs`. Screenshots and side-by-side comparisons: `docs/sift3/qa/impl/props/` (`scripts/v3-qa/props-shots.mjs`).

**Known differences from the mockups.** Default sort is Soonest (above); the "Has history" chip does not exist (the History threshold is a filter in the sheet); the filter sheet's Reset sits on the line under the shared sheet title (the shared sheet header owns the title row and close button); Research is absent for a player without a published profile (most NHL skaters: only some have profiles), instead of a button to nowhere; ranks use the publication's universe ("of 28" NFL teams, not 32); the sport rail and statistic chips come from today's data, so NBA appears; start times print in the viewer's time zone; the sheet's "Back to list" is a link that closes it. Locked facets (price move since open, teammate out, position-level defense) are notes with their reason, never controls.

## Milestone 7: Saved research and shell integration (done)

- Saved cards show the kind (Player, Team, Statistic, Game, Props), the sport, the state chips the screen saved ("L10", "Away", "6+") and the frozen values as **"Saved values"**. The earlier "At save (4m ago)" age text is gone: no ages or timestamps anywhere (freshness is internal).

## Hardening H-D: data correctness (branch `claude/sift3-h-data`)

Scope: non-tradable markets, scores, unavailable data, start times, saved research. Evidence for each item is in the tests named below; anything not verified is listed at the end.

### 1. Non-tradable markets never show an actionable ask

**What the publications carry** (measured on the captured real documents, 2026-10-26). Publication `event_detail` markets: `market_status` OPEN, SETTLED, UNKNOWN. Live-quote feed games (`sift.live_quotes.v1`): `status` active, inactive, determined (the captured DAL at PHI feed holds 76 `inactive` markets published WITH a yes ask, and 5 `determined`). Live store quotes: `rawStatus` (that word) and `availability` (OPEN, UNOPENED, SUSPENDED, CLOSED, SETTLED, UNKNOWN). The `inactive` markets are a real case: the old code printed their ask.

**The rule** (`src/v3/model/marketStatus.ts`, one vocabulary). A market is **not tradable only when its status word positively says so**: closed, determined, disputed, amended, expired, ended (closed); settled, finalized, finalised, resolved (settled); inactive, paused, suspended, halted, frozen, on hold (suspended); initialized, unopened, not open yet (not open); delisted, cancelled, voided, withdrawn (delisted). `open`/`active` are tradable. **A missing or unrecognised status word is not evidence**: it stays tradable and the quote gate still requires a current observation and a real ask. `Price` carries `tradable: boolean` and `marketStatus` (open, unopened, suspended, closed, settled, delisted, unknown); a non-tradable `Price` is built with no ask, bid or implied price.

**Where it is enforced.** (a) `data/quoteGate.ts` `gate()`: a non-tradable price is withheld whatever its age, with reason `not-tradable` (list "—"); an ask outside 1 to 99 cents is "no price" (the real `UNKNOWN` market with yes_ask 0.0 would otherwise print 0¢). (b) Every constructor sets the status from the observation it came from: `adapt.priceOf` (publication, or the live quote through `data/liveMarket.ts`, which keeps the provider's own word because the shared overlay folds words it does not know into UNKNOWN), `model/contract.priceOfQuote` (a quote with no ask but a non-tradable status is still a Price, so the sheet can say why), Prop Discovery `rawPrice` (live status when the live observation is newer, else the publication's). (c) Lists (lines, props, ladders, player props) are built only from markets that are not positively non-tradable. (d) `ui/ContractSheet.tsx`: a distinct state, "Market closed" / "Market settled" / "Trading suspended" (also "Not open for trading yet", "Market no longer listed"), a sentence, **no ask, bid, implied, fee or break-even rows and no Retry** (asking again cannot make it tradable); it keeps refreshing quietly, so a market that reopens shows its price. Research (Player History hit counts, lanes, ladders of other rungs, the screen itself) is not touched.

**Tests.** `tests/v3/marketStatus.test.ts` (66): every status word, the tradable rule, the gate for each non-tradable state with and without an ask and at any age, the real event_detail and the real live-feed `active`/`inactive`/`determined` markets (fixture `tests/v3/fixtures/live-feed-markets-by-status.json`: markets copied unchanged from the captured feed), Prop Discovery rungs, the overlay keeping the raw word. Cases with no real market (a `closed`/`settled` market that still has an ask) **modify one real market's status** and say so in the test name. `e2e/v3-nontradable.spec.ts` (real documents; the feed helper `freshQuotes` gained `status` to change one market's feed status): the real `inactive` market opens "Trading suspended"; `closed`, `determined`, `settled`, `finalized`, `paused` open the matching state; the open control is priced; a Game Detail props row prints "—" and its sheet says "Market closed" with the ladder intact; a game with every market non-tradable prints no price; the Games card carries no price; Prop Discovery row (props cache) prints "—" and opens "Trading suspended".

### 2. Scores

## Hardening: mobile performance

Branch `claude/sift3-h-perf`. Scope: everything except Prop Discovery's own load (H-B). Goal: real transferred bytes, first meaningful content and interaction responsiveness on a phone. Every change keeps the quote policy (`data/quoteGate.ts` stays the one display seam, no visible freshness, a withheld price is "—"), URL state, Back/scroll restoration and the 78 tap targets.

### Method (`scripts/v3-qa/screens-perf.mjs`)

The method of `props-perf.mjs`, generalised to every screen and fed from the committed fixture bundle instead of a scratch cache:

* **Documents** are answered by a local HTTP/2 + TLS server standing in for `raw.githubusercontent.com` (Chromium `--host-resolver-rules`; `--no-proxy-server` is required in this sandbox), from the fixture family the screen's spec uses (`e2e/support/feedSource`): Home, Games, Game Detail, Following, Explore from `game`; Player from `player`; Team from `team`; Stat from `stat`; Prop Discovery from `props`. Every body is gzip-encoded (level 6) with `cache-control: max-age=300` like GitHub; a document the family does not have answers 404; the quote-feed files are re-stamped to the family's pinned instant exactly as `freshQuotes`/`playerFeeds` do (timestamps only). Every other host is unresolvable.
* **App code**: a production build (`VITE_SIFT_UI=classic ... vite build`, the e2e build) served gzip-encoded over HTTP/2 (GitHub Pages is HTTP/2; the earlier HTTP/1.1 static server of `props-perf.mjs` over-states a 90-request module graph; `APP_H1=1` restores it).
* **Throttle** 9 Mbit/s down, 1.5 Mbit/s up, 170 ms latency, CPU 4x, 390x844 at DPR 2, touch, service workers blocked, `Date` pinned to the family's instant.
* **Bytes** are the browser's own (`Network.loadingFinished.encodedDataLength`, headers included). **Documents** are the requests to `raw.githubusercontent.com` (a HEAD existence probe is a request with no body; shown as "+ n"). **Time** is `performance.now()` from navigation start, median of 5 runs, the two builds alternating run by run (this machine is shared: its load average was 5 to 9 during the runs, so lead with bytes and document counts; times are relative to the other build measured in the same minute).

### What was found, and what changed

Before, every SIFT 3.0 screen, whatever it showed, loaded the same shell: the slate of all eight sports (26 to 30 documents) **plus the explorer index of every sport (8 documents, 811 KB on the wire; NBA's alone is 453 KB)** **plus one live-quote file per candidate game of every sport (33 to 43 files, polled again every 90 s; Prop Discovery 37)**. The explorer indexes were read only to decide, per sport, whether the live publication has an explorer (`data/source.ts` `doResolve`); the quote files were registered by the slate (`opportunity/load.ts` `useAllOpportunities`) so that opportunities could be re-priced, which SIFT 3.0 never prints. In the fixtures most of the 33 to 51 quote files do not exist (only the games a spec needs were captured: they answer 404 and count as documents, not bytes), so the byte saving of this item is understated here; on the live feed each existing file is 10 to 35 KB.

1. **Existence, not content, for the source decision** (`documentExists` in `data/fetcher.ts`, `data/source.ts`). While SIFT 3.0 is mounted, "does this sport's explorer exist?" is a HEAD request (a few hundred bytes) asked in parallel with the health document, instead of a read of the index after it. The reader keeps reading the index, once, for the screens that need it (Team, Player, Stat, Game for that sport). The probe is OFF for SIFT 2.0, classic and v4 (they read the document as before), falls back to a read when the host answers 405/501, and is a read through the swapped reader in every unit test. **Cost of the change (owner decision 1):** the source decision no longer validates the index's `schema_version`; a publisher that moved an index to an unsupported schema would now fail on the screen that reads it (with its honest state and Retry) instead of falling back to the saved copy at the source decision. -811 KB and -8 documents on every screen.
2. **The slate registers no quote and reads no settled-record document** (`useLeanOpportunities`, `v3/data/useSlate.tsx`). It prints no price; the screens that do (Games cards, Game Detail, Player, Props, the contract sheet) register exactly the contracts they print, as they already did, and the quote gate is untouched. The slate no longer re-computes whenever any quote changes. The NHL learning scorecard and the tennis record (29 KB of metrics plus the NHL and tennis indexes they needed, 156 KB) only feed an opportunity's record text; neither changes whether it is a candidate. Home's featured card prints no price either, so it no longer reads the game's contract document nor registers a detail-cadence quote scope (`useGameExtras(..., 'photo')`).
3. **Games reads a league's schedule only for a card that has been near the screen** (`GameCard`). One league's schedule is its explorer index (NBA 453 KB, tennis 130 KB).
4. **Following reads a sport's search index only to name a player followed in that sport** (it read all four: NBA's is 453 KB with the explorer index it is found through).
5. **The slate no longer re-renders every second.** The score store recomputes every second while games are observed and notified on every recompute; the slate subscribed to that and rebuilt ~600 games and re-rendered every screen reading it, once a second, for as long as the app was open (40 to 60 ms of main-thread time per second under the 4x throttle; visible in the trace as a timer task every second). `v3/data/scoreReads.ts` subscribes to a signature of what would be printed (verified score, clock, final, delayed) instead. Scores, the Delayed word and the verification rules are unchanged (`e2e/v3-scores.spec.ts`).
6. **Early start** (`v3/data/early.ts`, called from `v3/routes.tsx` when the entry script runs): for a `#/v3...` address the shell chunk, the screen's chunk, the slate's documents (health, board, recommendations of every sport in parallel instead of health, then board, then recommendations) and the entity a team, player, statistic or game address names (index, profile, metrics, contract document) are requested when the entry script runs, not after three lazy layers have mounted. The readers are the app's own memoised ones, so nothing is read twice; sample-data mode and Settings do nothing here; Statistic Detail does not start the slate early (the shell still reads it once mounted).
7. **CPU on the first screen**: one-pass featured-game pick (each game's tier computed once instead of inside a 600-game sort comparator; identical answers on 300 random slates, `tests/v3/perf.test.ts`), one `V3Team` per club and one view-model per slate row (so a re-derivation after a score or a schedule reuses them), chip rails measure once per frame instead of forcing a layout after every render (`ChipRail`: the measurement ran in a layout effect on every commit).
8. **Home's "What's happening"** reads its injury documents when the section is within 300 px of the screen (on a 390x844 phone it is: the list is at the fold, so the numbers below include them; on a shorter screen they wait).
9. **Fonts and the worker**: the two Barlow files that the classic page preloads are no longer preloaded for a `#/v3` address (45 KB v3 never draws; `vite.config.ts`), and on a `#/v3` address the service worker registers 6 s after load instead of at start-up (`main.tsx`): a first visit installs the worker, which downloads the whole app in the background (267 files, 1.6 MB on the wire); that no longer shares the connection with the first screen. Not measured by the harness (service workers are blocked there, as in `props-perf.mjs`).

### What did not improve, and why

* **Team and Statistic first content is only slightly faster.** Their first screen is gated by their own chain (health, explorer index, profile, one more document) and by a main thread that is busy computing the slate for the shell (the CPU is the limit: under the 4x throttle the first screen runs ~1.1 s of module evaluation and ~0.6 s of React and slate work). The early start of the entity (index and profile requested at entry time) took the tail of that chain off but cannot take the shared CPU work off.
* **Interaction responsiveness is mostly render time, not bytes.** Tab and chip taps paint in 100 to 550 ms under the 4x throttle (a few tens of ms of real CPU); the two slow ones are Game Detail's Matchup tab (1.0 s: both team profiles, the ranking documents they point to, then the largest render in the app) and opening a game from a card (about 1 s: the game chunk, its contract document, the render). Those documents are read when the tab or the screen asks for them, which is the point of lazy reading; reading them ahead would cost bytes on every visit to save a round trip on some.
* **Explore (search) still reads 678 KB.** The search covers four sports and each needs its explorer index (the file table; NBA's is 453 KB) only to find its search index (14 KB). I made the read wait for the first focus or keystroke and reverted it: the search icon opens Explore with the field focused (so the saving never applied to the real path), and `e2e/v3-unavailable.spec.ts` rightly asserts that a failed search index is said out loud when Explore opens. Needs the publisher: a small search manifest.
* **Games still pays one league schedule per league shown and one contract document per card shown.** The start-time authority (H-D) is the league's explorer index (NBA 453 KB, tennis 130 KB) and a card's lines come from the game's `event_detail` (0.3 to 1.3 MB raw). Opening Games on NBA (76 upcoming games) reads 99 documents as the list scrolls. Needs the publisher: a per-league schedule document and a per-game lines document.
* **The app code is still 725 to 750 KB on the wire in ~90 requests for the first screen** (it was 770 to 795 KB). The entry chunk carries ~250 KB of classic views (CBB 67 KB, broadcast, game, home, markets, board) that SIFT 3.0 never draws, and 23 classic stylesheets (97 KB gzip, render-blocking) are imported by `main.tsx` for every address; the fonts are 173 KB (Geist 400/500/600/700 at 35 KB each, Sora 34 KB). A v3-only entry would remove roughly 170 KB; it touches the entry that classic and v4 share, so it is not done here. Merging small chunks was tried (Rolldown `codeSplitting` group over the shared libraries: 91 to 55 requests, +27 KB, first content within noise) and not kept.
* **Prop Discovery** gains only what the cheaper shell gives it (documents 101 to 61, 1,673 to 1,386 KB, first content 5.5 to 4.7 s); its own load is H-B's.

### Owner decisions

1. **Source decision without the index's schema check** (item 1 above): accept, or keep the full read for sports whose HEAD succeeded (costs the 811 KB back).
2. **Publisher backlog** for the three costs left above: a small per-sport search manifest, a per-league schedule document, a per-game lines document (`BACKEND_BACKLOG.md`).
3. **First-visit worker install** (267 files, 1.6 MB): it now starts 6 s after load on a `#/v3` address. Say if the precache should be narrower (SIFT 3.0's shell only) or on demand.
4. **A v3-only entry** (about 170 KB less code and the classic stylesheets off the first screen) and **a variable Geist** (one file instead of four, about -80 KB, a new dependency): both are possible; both change shared build inputs.
5. Home lists up to four games' injury items; on a phone that list is at the fold, so four 17 KB documents (about 70 KB) are read with the first screen. Two games would halve it.

### A. Unknown, suspended, closed, settled and expired market prices are not actionable offers

Supersedes "A missing or unrecognised status word is not evidence" in H-D section 1. Rule (`src/v3/model/marketStatus.ts`, still the one vocabulary; the delivery chain's table, `claude/quote-track:src/live/tradable.ts`, is checked word for word in `tests/v3/marketStatus.test.ts`; v3 imports nothing from `src/live`):

| Status word | State | Actionable? | Contract sheet |
|---|---|---|---|
| open, active, trading | open | yes (the quote gate still needs a current observation and a 1 to 99 cent ask) | prices |
| (no status at all; a live quote with `rawStatus` null and availability UNKNOWN) | unreported | yes (same gate) | prices |
| closed, determined, disputed, amended, ended | closed (terminal) | no, at any age | Market closed |
| settled, finalized, finalised, resolved, voided, void, cancelled, canceled; any non-empty `result` | settled (terminal) | no, at any age | Market settled |
| expired, expiry | expired (terminal) | no, at any age | Market closed |
| delisted, removed, withdrawn, archived | delisted (terminal; v3's own word) | no, at any age | Market no longer listed |
| inactive, paused, suspended, halted, trading_halted, frozen, on hold | suspended | no | Trading suspended while the observation is current; an old report reads "Price unavailable right now" with Retry |
| initialized, initialised, unopened, not open, not yet open | unopened | no | Not open for trading yet (same age rule) |
| any other non-empty word, the app's own UNKNOWN included | unrecognised | no | Price unavailable right now, Retry, no ask, bid, implied, fee or break-even rows |

Enforcement is unchanged in shape: `Price.tradable`/`marketStatus` is set where a Price is made (`adapt.priceOf`, `model/contract.priceOfQuote`, Prop Discovery `rawPrice`, all through `liveStatusWord`/`statusFacts`), lists are built only from markets whose word is open or absent (`adapt`, `props/parse`, and `research/gameMarkets`, which had its own copy of the rule that let UNOPENED through), and `data/quoteGate.ts` withholds a non-tradable Price at any age. A live observation that sent no status leaves the publication's word standing (`overlayLive`, `rawPrice`), and `newerPrice` does not let a status-less newer observation reopen a terminal one. Lists print "—"; Games, Home, Game Detail, Prop Discovery rows, compare and peek, Player ladder and decision card, and the sheet all read the same gate. Historical research (History lanes, hit counts, the screen itself) is not touched.

### B. Every consumed document is validated at the point of consumption

`src/v3/data/validate.ts`: dependency-free, typed guards per kind of document returning `{ ok, doc }` or `{ ok: false, reason, unsupported? }`. `getJson` calls them through `setDocumentValidator` (default off; installed by `applyV3FetchBounds`, removed when V3Root unmounts), so SIFT 2.0 and classic accept what they always accepted. A rejected document is never memoised and never partly drawn. A `schema_version` other than `edge_finder.app.v1` (or none) throws `SchemaVersionError` ("it is in a format this version of SIFT cannot read", no Retry); anything else throws `DocumentInvalidError` ("what was published could not be read", Retry). **One rule.** `src/live/quoteUsable.ts` is the single source of truth for "is this quote usable and actionable" in SIFT 3.0.

- `data/quoteGate.ts` keeps its v3 API (`gate`, `usablePrice`, `maxAgeMs`, `observationCurrent`, `QuoteContext`, `GateResult`) and delegates the age table, the start tiers, the 5 s future tolerance, the device-clock skew and the "an answer the provider did not time is no observation" rule to `quoteUsable`. What it still decides itself is what only a v3 `Price` has: an ask of 1 to 99 cents, a status already resolved to a state, labelled sample data. No age, label or timestamp is shown.
- `model/marketStatus.ts` judges every status word, `result` and live quote with `src/live/tradable.ts` (`marketStatusOf`); v3 only refines words that module calls `unrecognised` into the state they name (`ended` is closed, `on hold` is suspended, `delisted`/`removed`/`withdrawn`/`archived` are v3's terminal "no longer listed"), and never makes anything tradable. A live quote is judged whole, so a non-empty `result`, a close time already passed on a quote with no status, and the more restrictive of word and availability now apply to v3 prices too.
- `Price.observedVia` carries an untimed ('received') live answer through: it is never usable and never replaces a timed observation (`newerPrice`).

**Equivalence with the approved table** (`tests/v3/quoteUsableEquivalence.test.ts`, 261 tests): every row (list >2 h 180 s, <=2 h 90 s, live 60 s; contract >2 h 60 s, <=2 h or live 30 s; unknown start the stricter tier), the exact limit and one millisecond over, future observations (-1 s, -3 s, -5 s usable; -5.001 s and further rejected), missing/blank/unparseable/untimed observations, skew in both directions, the tier transitions at 2 h and at the start, and a 2 x 2 x 12 x 19 grid, both implementations against the table and against each other. **Discrepancies found in the previous v3 implementation (before this change):** (1) a LIST whose scheduled start had passed, with no `live` flag, got the "within 2 hours" limit (90 s); the shared rule treats a start in the past as live (60 s).
