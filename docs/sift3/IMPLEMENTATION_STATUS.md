# SIFT 3.0 implementation status

Branch `claude/sift3-impl`, stacked on `claude/sift3-build` (PR #147, draft). Everything is behind the single `#/v3` opt-in. Order (approved 2026-10-26): 0 Foundations, 1 Data layer, 2 Stat Detail and League Rankings, 3 Player Research, 4 Team Research, 5 Game Detail and Matchup, 6 Prop Discovery, 7 Saved research and shell, 8 Hardening. Quote engineering runs on its own branch (`claude/quote-track`, see `docs/quote-track/README.md` there).

## Milestone 0: Foundations (done)

**Contracts now in code**

| Contract | Where | What it guarantees |
| --- | --- | --- |
| Versioned URL state | `src/v3/state/url.ts`, `src/v3/nav/schemas.ts` | One schema per screen (player, team, stat, game, props). Decoding never throws and falls back per field; encoding omits defaults and is deterministic; `v=1` is written whenever a field is. Parameters without `v` are version 0 and migrate forward (`?tab=rankings&team=DAL` becomes `ranking`, `sel=DAL`). Unknown and shell parameters pass through. |
| In-place changes never add history | `useRouteState`, `useQueryPatch` | Tab, window, line, filter, sort and typed text replace the entry; Back therefore leaves the screen, and the entry below keeps its own state. Several updates in one handler compose. |

Links inside a sheet replace the sheet entry with the destination, so Back lands on the screen underneath with every sheet closed. A state change made inside a sheet is applied to the screen underneath after the sheet closes. Addressed sheets (`?sheet=contract&tk=...`) are deep-linkable and registered with `registerSheet`. |
| Scroll memory | `src/v3/state/scroll.ts` | Per history entry; committed on arrival before anything scrolls; in-place changes never move the page; a new screen starts at the top; reload falls back to the address; shell parameters are not part of the page key. |

| Saved research | `src/v3/model/saved.ts`, `state/prefs.ts` | The existing record (route with query, title, subtitle, snapshot) is kept and extended with `v`, `kind`, `sport`, `chips`, `sv`. First-build records open unchanged. |
| Sport capabilities | `src/v3/model/capabilities.ts` | Per sport, per section: `ready`, `gated` (published but not shown, with the reason) or `none`. NFL full; NHL Overview and Form for team research; MLB team research gated (late-August cache); no sport is hard-coded into a screen. |
| Ink and graphite tokens | `src/v3/v3.css` and the screen stylesheets | The locked palette applies app-wide (shell, Home, Games as well as research screens) so there is one visual system. Cyan, semantic colours and team colours unchanged. |
| Shared atoms | `src/v3/ui/atoms.tsx`, `atoms.css` | Lane marks and the three-lane readout (Market square, History ring, SIFT model diamond, never blended), ladder track, percentile track, tabs, segmented control, chips, locked row. ## Milestone 6: Prop Discovery (PD1 to PD6)

Branch `claude/sift3-m6-props`. Route `/v3/props` (lazy; Prop Discovery owns the address, it is never handed to the classic `/:slug/props` route). One address holds the home (`view` absent), the list (`view=list`, implied by any list field) and the comparison (`view=compare`); sort, filters, search text, selections, compare mode, the expanded row (`exp=id` or `id@k` for another rung) and `pin` are all in it, in place changes replace history, typed text never adds an entry per keystroke.

**Explore tab decision.** The Explore tab is rooted at Prop Discovery (the locked walkthrough's `E.nav` roots Explore at the Prop Discovery home). The older search screen stays at `/v3/explore` under the same tab and keeps working (the Home and Games search icons, Following's "find teams and players" and the stat search journey all open it); the PD home search field searches props only. Tab lighting: Games for Team, Player and Game; Explore for Stat Detail, Prop Discovery and the older search.

**Universe (cost bound).** There is no all-games prop manifest, so the universe is a join of published documents read lazily and shared with the rest of the app: per game `event_detail` (the contract ladders; 0.3 to 1.3 MB each), the sport's explorer index (roster to team, which players have a profile), the NFL history index, event research for injuries where the game's own document carries none, the projection feed only for sports with an approved model, and one ranking document per opponent unit. A game enters the universe when it is real, pre-game, in a sport `capabilities.ts` marks `propPrices: ready`, starts within 48 hours (`PROP_HORIZON_MS`) and its board row says at least one market is listed. This is what keeps a 300-game college slate (0 player markets today) from costing 600 documents. No player log is read up front: History is computed for rows on screen (after the viewer pauses), the expanded row and card shelves, from the NFL history file (about 7 KB per player) or the NHL player profile's game log (about 28 KB).

**Default sort.** The design's default is History hit rate; ranking 335 or 1000 rows by it needs every player's log and no bulk published summary exists. The default is therefore Soonest (needs no log). Sorting or filtering by History loads logs only on request: up to 30 missing logs load automatically, beyond that the list says "Load history for N more players (about X KB)" and ranks only rows whose log is loaded, saying so. A row without a loaded log never ranks above one that has it and never passes a History threshold; nothing is faked.

**Lanes.** Market is the gated pre-fee ask; History is hits over the last 10 games from the player's log; SIFT model is shown only where the approval ledger approves the family AND the published projection passes its checks (`lib/projectionApprovals.ts`, `lib/projectionAuthority.ts` through `data/props/model.ts`): today NFL receptions and completions and MLB pitcher outs and strikeouts. Everything else is "—" with the reason ("not approved yet"; NHL skaters are under validation). The lane is never blended, subtracted or sorted against Market; no "edge" or "value" wording exists.

**Prices.** Only through `data/quoteGate.ts` (list context for rows, contract context in the exact-contract sheet). A withheld price is "—" in rows, cards, rung chips and compare; the sheet shows "Price unavailable right now" with Retry and hides ask, bid, implied, fee and break-even. Rows register their tickers at the `game` cadence only after they have stayed on screen for 450 ms; opening a row asks once for its whole ladder (`refreshNow`). Seam for `claude/quote-track`: `usePropPrices` (`addRowsScope`) and the open-row refresh (`refreshContract`). With the current feed (3.5 minutes plus a 5-minute CDN cache behind, and no NBA/CFB/CBB games in it) most list prices are withheld by the approved age rule until the relay carries them: that is the rule working, not a defect.

**Real-document tests.** `e2e/v3-props.spec.ts` (23 tests) runs on the cached real documents under a fixed browser clock (`feedNow()` in `e2e/support/realFeeds.ts`, written to `.v3-feed-cache/captured_at.txt`; real-document caches describe one instant) and `freshQuotes()` re-stamps only the quote feed's observation times (a test transformation; prices untouched) or makes the feed fail for the missing-price states. Unit tests: `tests/v3/props-data.test.ts` (24) and `tests/v3/props-universe.test.ts` (12). WebKit: `scripts/v3-qa/props_wk.py` (48 checks at 390x844 and 375x667) and `journeys.py` (48). Performance probe: `scripts/v3-qa/props-perf.mjs`. Screenshots and side-by-side comparisons: `docs/sift3/qa/impl/props/` (`scripts/v3-qa/props-shots.mjs`).

**Known differences from the mockups.** Default sort is Soonest (above); the "Has history" chip does not exist (the History threshold is a filter in the sheet); the filter sheet's Reset sits on the line under the shared sheet title (the shared sheet header owns the title row and close button); Research is absent for a player without a published profile (most NHL skaters: only some have profiles), instead of a button to nowhere; ranks use the publication's universe ("of 28" NFL teams, not 32); the sport rail and statistic chips come from today's data, so NBA appears; start times print in the viewer's time zone; the sheet's "Back to list" is a link that closes it. Locked facets (price move since open, teammate out, position-level defense) are notes with their reason, never controls.

## Milestone 7: Saved research and shell integration (done)

- Saved cards show the kind (Player, Team, Statistic, Game, Props), the sport, the state chips the screen saved ("L10", "Away", "6+") and the frozen values as **"Saved values"**. The earlier "At save (4m ago)" age text is gone: no ages or timestamps anywhere (freshness is internal).

## Hardening: reproducible real-document tests

Branch `claude/sift3-h-fixtures`. The real-document Playwright specs no longer depend on an uncommitted disk cache: the published documents they read are committed (sanitized, deduplicated, with provenance and capture metadata) in `fixtures/real/`, and the specs read them offline on each family's pinned clock. Reference: `fixtures/real/README.md`.

**What is committed.** Five families, never merged because they describe different instants: `stat` (`v3-stat`), `team` (`v3-team`), `game` (`v3-game`, `v3-quotegate`, `v3-hit-targets`), `player` (`v3-player`), `props` (`v3-props`). 358 URLs map to 182 unique documents (61.9 MB if each family kept its own copy, 33.4 MB deduplicated); the packs are 3,097,492 bytes of gzip and the whole directory is 3.35 MB (largest file 1.3 MB; the five worker caches held 1,770 documents, about 113 MB of JSON, of which 1,412 (1,293 of them in the props cache) are never requested by that family's specs and are therefore not committed). Format: `index.json` (URL to document hash and status, document hash to pack/offset/length, clock per family) plus `packs/*.bin.gz` (gzip of the concatenated byte-exact bodies), so a browser-side shim can read it with `fetch` and `DecompressionStream` (`scripts/v3-fixtures/webLoader.mjs`, the reference reader, unit-tested). `MANIFEST.json` carries the provenance: source repositories and branches (from `src/data/sports.ts` plus the live-quotes, router-registry and CFB-signals branches), capture window and clock pin with its basis per family, tool version and git sha, and per document the original URL, status, sha256, byte count, content type and fetch time, plus a terms note (public data, no endorsement).

**Tooling (`scripts/v3-fixtures/`).** `capture` (live fetch through curl into a scratch cache, journaling URL, status, content type, sha256 and fetch time), `pack` (cache to one family of the bundle: scan, dedup, drop unrequested documents), `verify` (sizes, pack and document hashes, index equals manifest, URL hygiene, JSON shapes, clocks, orphans, sanitization re-scan; run in CI and by `tests/v3/fixtures-bundle.test.ts`), `unpack` (a family back to a scratch cache, or one document to stdout). Sanitization fails packing and verification on private keys, tokens, JWTs, `Authorization`/bearer credentials, API-key or secret fields, e-mail addresses, phone and SSN-shaped numbers, credentials or secrets in URLs, private-network URLs, non-`raw.githubusercontent.com` hosts; the scan found nothing in the 182 documents and there are no allow-list entries. Bodies are never altered.

**Loader.** `useRealFeeds(page, { family })`, `freshQuotes(page, { family })`, `feedNow(family)` (`e2e/support/realFeeds.ts`) and `usePlayerFeeds` (`playerFeeds.ts`, family `player`) answer `raw.githubusercontent.com` requests from the committed bundle by default (`e2e/support/feedSource.ts`); a missing document answers 404 exactly as before. `V3_REAL_FEEDS=live` refills a scratch cache (`V3_FEED_CACHE` or `.v3-feed-cache`, gitignored) through curl and journals it; `V3_FEED_CACHE=<dir>` alone serves only that scratch cache; `V3_FEED_RECORD=<file>` logs every document request (how the needed set is found). Clocks come from the manifest (`V3_FEED_NOW` overrides). Two specs edited a real document with `route.fetch()`, which goes to the network and ignores the fixture (`v3-stat` empty-series test, `v3-team` row 61); they now read the document with `feedDocument(family, url)`. `v3-stat` and `v3-team` now pin the family clock (they ran on the wall clock before, so tests about the next opponent (DAL at PHI, kickoff 2026-10-27T00:15Z) failed once that game had been played: stat 29 of 32 and team 19 of 23 passed on 2026-10-27 18:00Z against the original caches; with the pin, all pass). The stat/team pin (2026-10-26T23:25:00Z) was not recorded with those caches; it is the instant of the game and props families, inside the capture windows, and verified by the specs passing (recorded in the manifest as such). `tests/v3` and `src` are untouched.

**CI.** `.github/workflows/v3-ci.yml` (new; `ci.yml` is untouched): on `pull_request` (paths `src/v3`, `e2e`, `tests`, `fixtures`, `scripts/v3-fixtures`, `playwright.v3.config.ts`, `package.json`, the lockfile and the workflow itself) and `workflow_dispatch`; `permissions: contents: read`; no secrets. Jobs: `static` (`tsc -b`, eslint, `vitest run`, fixture verify with a size budget), `build` (`npm run build:e2e` once, uploaded), and an `e2e` matrix of `v3-phone` (Chromium, Pixel 7), `v3-iphone` (WebKit, iPhone 15 Pro) and `v3-iphone-se` (WebKit, iPhone SE 3rd gen), each with the same patient bounded install as `ci.yml` (only the engine the project needs), the production build served by `scripts/e2e-preview.mjs` at the Pages base path (higher fidelity than the dev server: the shipped bundle, no on-demand transform racing the first requests), job timeouts, failure context in the log and traces/screenshots uploaded on failure. `playwright.v3.config.ts`: projects are individually selectable (`V3_PROJECTS=v3-iphone`), WebKit is included automatically when `CI` is set or `V3_WEBKIT=1`, `V3_SERVER=preview` serves the production build, unknown project names are an error. **WebKit could not be run here**: Playwright's WebKit build cannot be downloaded in this sandbox, so `v3-iphone` and `v3-iphone-se` have never run in this repository's Playwright; the first CI run is their first execution, and they may expose WebKit-only differences.
