# SIFT 3.0 implementation status

Branch `claude/sift3-impl`, stacked on `claude/sift3-build` (PR #147, draft). Everything is behind the single `#/v3` opt-in. Order (approved 2026-10-26): 0 Foundations, 1 Data layer, 2 Stat Detail and League Rankings, 3 Player Research, 4 Team Research, 5 Game Detail and Matchup, 6 Prop Discovery, 7 Saved research and shell, 8 Hardening. Quote engineering runs on its own branch (`claude/quote-track`, see `docs/quote-track/README.md` there).

## Milestone 0: Foundations (done)

**Contracts now in code**

| Contract | Where | What it guarantees |
| --- | --- | --- |
| Versioned URL state | `src/v3/state/url.ts`, `src/v3/nav/schemas.ts` | One schema per screen (player, team, stat, game, props). Decoding never throws and falls back per field; encoding omits defaults and is deterministic; `v=1` is written whenever a field is. Parameters without `v` are version 0 and migrate forward (`?tab=rankings&team=DAL` becomes `ranking`, `sel=DAL`). Unknown and shell parameters pass through. |
| In-place changes never add history | `useRouteState`, `useQueryPatch` | Tab, window, line, filter, sort and typed text replace the entry; Back therefore leaves the screen, and the entry below keeps its own state. Several updates in one handler compose. |
| Sheets are history entries | `src/v3/ui/Sheet.tsx`, `nav/sheetBridge.ts` | Opening pushes one entry; Back, the X, the backdrop and Escape all close it and leave no ghost entry. Links inside a sheet replace the sheet entry with the destination, so Back lands on the screen underneath with every sheet closed. A state change made inside a sheet is applied to the screen underneath after the sheet closes. Addressed sheets (`?sheet=contract&tk=...`) are deep-linkable and registered with `registerSheet`. |
| Scroll memory | `src/v3/state/scroll.ts` | Per history entry; committed on arrival before anything scrolls; in-place changes never move the page; a new screen starts at the top; reload falls back to the address; shell parameters are not part of the page key. |
| One route builder, one set of targets | `src/v3/nav/routes.ts`, `nav/Targets.tsx` | `TeamLink`, `PlayerLink`, `StatLink`, `GameLink`, `PropsLink`, `PriceTap`, `NavRow` (stretched row link with independent raised targets, never an anchor inside an anchor). Every target carries `data-tap` and `data-dest`; hit areas are at least 44 points without changing layout. |
| Saved research | `src/v3/model/saved.ts`, `state/prefs.ts` | The existing record (route with query, title, subtitle, snapshot) is kept and extended with `v`, `kind`, `sport`, `chips`, `sv`. Every stored record is validated and migrated on read (`reviveSaved`); unopenable records are dropped, routes are canonicalised, duplicates collapse, ids stay unique. First-build records open unchanged. |
| Sport capabilities | `src/v3/model/capabilities.ts` | Per sport, per section: `ready`, `gated` (published but not shown, with the reason) or `none`. NFL full; NHL Overview and Form for team research; MLB team research gated (late-August cache); no sport is hard-coded into a screen. |
| Ink and graphite tokens | `src/v3/v3.css` and the screen stylesheets | The locked palette applies app-wide (shell, Home, Games as well as research screens) so there is one visual system. Cyan, semantic colours and team colours unchanged. |
| Shared atoms | `src/v3/ui/atoms.tsx`, `atoms.css` | Lane marks and the three-lane readout (Market square, History ring, SIFT model diamond, never blended), ladder track, percentile track, tabs, segmented control, chips, locked row. Chart-specific atoms (hit bars, league dot plot, margin bars) arrive with their screens. |
| Tap matrix | `tests/v3/tapmatrix.ts` | The walkthrough's 78 targets as data, each assigned to its milestone. A milestone is complete only when its rows pass against the real components. |

## Milestone 1: Data layer (done, in `src/v3/data/research/`)

Typed, tested normalizers over the real published documents, and lazy cached hooks. Screens read these; none reads a contract document directly.

| Piece | What it gives |
| --- | --- |
| `normalizeTeamProfile` / `useTeamProfile` | One team document answers the whole statistic list: every metric and window with the published rank, universe size (28 NFL teams in the current packet, not 32), percentile, ranking id and higher-is-better flag. Games with results from the team side, availability, players, series refs. |
| `teamRecord` | NFL: counted from completed regular-season results of the current season. NHL: wins, regulation losses and overtime losses separately; the publication's own stated record is used when it carries one (`7-4-2` for 2026-27 today), else derived from the official points percentage, else none (never an unreconcilable guess). |
| `buildRankingCatalog` / `useRankingCatalog` | (metric, window) to ranking id, read from the profiles' own ranking lists (authoritative), not from label matching. |
| `normalizeRanking` / `useRankingDoc` | A ranking fetched only when a statistic is opened, with its universe, summary, limitations and adjusted flag. |
| `scheduleOf` / `useSchedule` / `nextGame` | The schedule authority: explorer start times; Kalshi event times are never used as a start. |
| `deriveRelated` (temporary) | Related statistics from stable ids, validated against the sport's registry, raw and adjusted typed apart, never crossing sport or entity type. Replaced by backend backlog item 1. |

Not in this milestone, by design: the cross-game prop index (Prop Discovery, milestone 6, where its consumer is), and quote usability wiring (waits on the separately reviewed quote branch; screens use one seam, `src/v3/data/quoteGate.ts`, so swapping in `quoteUsable` is a one-file change).

Real-document test tooling: `e2e/support/realFeeds.ts` answers feed requests from a disk cache of real published documents (`V3_REAL_FEEDS=live` fills it with curl through the environment proxy); `scripts/v3-qa/shot.mjs` takes phone screenshots (`REAL=1` for real data). Fixtures in `tests/v3/fixtures` are trimmed real documents captured 2026-10-26.

## Milestone 3: Player Research (P1 to P4, plus Trends, Log and SIFT Replay)

Branch `claude/sift3-m3-player`. Route `/v3/player/:slug/:playerId`; the tab bar is the mockup's five tabs: Overview, Props (count badge), Matchup, Trends, Log. Sports: NFL full; NBA (and NHL where box logs are published) from the published box logs; MLB prices only (`isReady(slug,'playerResearch')` is gated); every other sport says it is not available. Only the opened player's log and that game's markets are read (lazy, cached); opponent ranks and the team schedule are fetched only when a tier filter, the Matchup tab, a Log or a selected bar needs them.

**Locked states, all functional:** P1 hero (photo, credited, team identity, availability chip from the published projection row, follow and save), game strip with both logos and the next game, tab bar, statistic pills with the filter button and count badge, decision card (selected line, Over price, Market / History / SIFT model lanes), window chips with hit counts, the hit-bar chart with the line and the coming game's bar, summary strip. P2: the line drags with a finger (pointer events, `touch-action: none` on the line's label and gutter only), snaps to the Kalshi rungs, the readout replaces the window chips while scrubbing, bars recolour and every number updates; the alt-line ladder (three lane marks per rung) and its sheet. P3: research-filters sheet with the live "N games match" card, a count and hit rate on every option before it is applied, applied-filter chips, and visibly locked rows (Favorite, Teammate out, Weather, Pace) that are notes, never controls. P4: Matchup with the opponent unit's league strips (each a target to Stat Detail with the opponent highlighted), the projection build, availability, and the honest "No matchup rows" state.

**Inferred (no locked image):** Trends (windows table with hit, average, median and distance from the line; Splits with the same cuts as the filters sheet and their sample sizes; a row applies the cut on the chart; a link to SIFT Replay), Log (window chips and one row per game, newest first, the statistic and whether it cleared the line, the other statistics in one line, row opens Game Detail where the schedule lists the game, opponent logo is a team target), and the SIFT Replay view (`tab=trends&view=replay&rmode=similar|h2h`: comparable observed games, summary, chart, rows, and the honest "Adjusted what-if: not available"). All built from the screen's own atoms; no number appears there that another tab could not show.

**Address.** `playerSchema` is version 2 (tab, stat, line, win, site, opp, tier, rest, script, role, min, res, obs, view, rmode, more). Migrations from 0 and 1: `tab=replay` becomes Trends with Replay open (mode kept), `tab=log` stays Log, an unknown tab is Overview, `win=L20` becomes `ALL`. The pre-lock filter values (`rest=normal`, `script=close|blowout`) still decode. In-place changes replace history; sheets push one entry; Back restores line, window, filters, tab and scroll with the filters and contract sheets closed.

**Exact-contract sheet** (`src/v3/ui/ContractSheet.tsx`, addressed `?sheet=contract&tk=`, registered with `registerSheet`; Prop Discovery reuses it): Over price, implied, taker fee and fee-aware break-even from the ask with the one fee schedule in `model/format.ts`; "pre-fee" labelled; prices only through `data/quoteGate.ts`; withheld is exactly "Price unavailable right now" with Retry, fee and break-even hidden; lists show "—"; no freshness text anywhere. On open (and on Retry) it asks the shared live-quote store for a forced refresh of that one ticker (`QuoteStore.refreshNow`, which exists); the quote-track branch's contract-context request replaces that one call (seam commented in the file). `src/live` is not modified.

**The SIFT model lane and the approval ledger (one story).** A model number appears only if (1) the app's projection authority resolves it as authoritative for that player, stat and game, AND (2) the approval ledger (`src/lib/projectionApprovals.ts`) row for that stat is PROMOTED to the foundation engine (and its publication standard is not NOT_MET); `siftLaneFor` re-checks (2) itself. The screen carries the record: the lane has `data-ledger="NFL:receptions:PROMOTED:2026-10-18"` and Matchup stages carry theirs. Found per stat: NFL receptions, targets, team pass attempts, team rush attempts: PROMOTED 2026-10-18 (team attempts "MET_WITH_CAVEATS", the caveat is shown); NFL receiving yards, carries, rushing yards, touchdowns (anytime TD), passing yards and attempts: HELD (lane "—", "not approved yet"); NFL passing TDs: RETAINED ("not approved yet"); NFL completions: PROMOTED; NBA points, rebounds, assists, threes, PRA: APPROVED_PENDING_LIVE_INPUTS, the established engine stays the one number, so the lane is "—" with "awaiting live inputs"; NHL goals, assists, points: RETAINED, "—"; MLB: prices only. The mockup's "research-only" chip was the publication's document-level flag (every projection document says `authority: research_only`: context, never betting authority), not the ledger; Matchup now says "3 of 4 approved" from the same ledger, and the lane footer says "approved model estimate" only when a number is shown. Tests: `tests/v3/siftLane.test.ts`, e2e "SIFT model lane only where the approval ledger allows it".

## Milestone 6: Prop Discovery (PD1 to PD6)

Branch `claude/sift3-m6-props`. Route `/v3/props` (lazy; Prop Discovery owns the address, it is never handed to the classic `/:slug/props` route). One address holds the home (`view` absent), the list (`view=list`, implied by any list field) and the comparison (`view=compare`); sort, filters, search text, selections, compare mode, the expanded row (`exp=id` or `id@k` for another rung) and `pin` are all in it, in place changes replace history, typed text never adds an entry per keystroke.

**Explore tab decision.** The Explore tab is rooted at Prop Discovery (the locked walkthrough's `E.nav` roots Explore at the Prop Discovery home). The older search screen stays at `/v3/explore` under the same tab and keeps working (the Home and Games search icons, Following's "find teams and players" and the stat search journey all open it); the PD home search field searches props only. Tab lighting: Games for Team, Player and Game; Explore for Stat Detail, Prop Discovery and the older search.

**Universe (cost bound).** There is no all-games prop manifest, so the universe is a join of published documents read lazily and shared with the rest of the app: per game `event_detail` (the contract ladders; 0.3 to 1.3 MB each), the sport's explorer index (roster to team, which players have a profile), the NFL history index, event research for injuries where the game's own document carries none, the projection feed only for sports with an approved model, and one ranking document per opponent unit. A game enters the universe when it is real, pre-game, in a sport `capabilities.ts` marks `propPrices: ready`, starts within 48 hours (`PROP_HORIZON_MS`) and its board row says at least one market is listed. This is what keeps a 300-game college slate (0 player markets today) from costing 600 documents. No player log is read up front: History is computed for rows on screen (after the viewer pauses), the expanded row and card shelves, from the NFL history file (about 7 KB per player) or the NHL player profile's game log (about 28 KB).

**Default sort.** The design's default is History hit rate; ranking 335 or 1000 rows by it needs every player's log and no bulk published summary exists. The default is therefore Soonest (needs no log). Sorting or filtering by History loads logs only on request: up to 30 missing logs load automatically, beyond that the list says "Load history for N more players (about X KB)" and ranks only rows whose log is loaded, saying so. A row without a loaded log never ranks above one that has it and never passes a History threshold; nothing is faked.

**Lanes.** Market is the gated pre-fee ask; History is hits over the last 10 games from the player's log; SIFT model is shown only where the approval ledger approves the family AND the published projection passes its checks (`lib/projectionApprovals.ts`, `lib/projectionAuthority.ts` through `data/props/model.ts`): today NFL receptions and completions and MLB pitcher outs and strikeouts. Everything else is "—" with the reason ("not approved yet"; NHL skaters are under validation). The lane is never blended, subtracted or sorted against Market; no "edge" or "value" wording exists.

**Prices.** Only through `data/quoteGate.ts` (list context for rows, contract context in the exact-contract sheet). A withheld price is "—" in rows, cards, rung chips and compare; the sheet shows "Price unavailable right now" with Retry and hides ask, bid, implied, fee and break-even. Rows register their tickers at the `game` cadence only after they have stayed on screen for 450 ms; opening a row asks once for its whole ladder (`refreshNow`). Seam for `claude/quote-track`: `usePropPrices` (`addRowsScope`) and the open-row refresh (`refreshContract`). With the current feed (3.5 minutes plus a 5-minute CDN cache behind, and no NBA/CFB/CBB games in it) most list prices are withheld by the approved age rule until the relay carries them: that is the rule working, not a defect.

**Real-document tests.** `e2e/v3-props.spec.ts` (23 tests) runs on the cached real documents under a fixed browser clock (`feedNow()` in `e2e/support/realFeeds.ts`, written to `.v3-feed-cache/captured_at.txt`; real-document caches describe one instant) and `freshQuotes()` re-stamps only the quote feed's observation times (a test transformation; prices untouched) or makes the feed fail for the missing-price states. Unit tests: `tests/v3/props-data.test.ts` (24) and `tests/v3/props-universe.test.ts` (12). WebKit: `scripts/v3-qa/props_wk.py` (48 checks at 390x844 and 375x667) and `journeys.py` (48). Performance probe: `scripts/v3-qa/props-perf.mjs`. Screenshots and side-by-side comparisons: `docs/sift3/qa/impl/props/` (`scripts/v3-qa/props-shots.mjs`).

**Known differences from the mockups.** Default sort is Soonest (above); the "Has history" chip does not exist (the History threshold is a filter in the sheet); the filter sheet's Reset sits on the line under the shared sheet title (the shared sheet header owns the title row and close button); Research is absent for a player without a published profile (most NHL skaters: only some have profiles), instead of a button to nowhere; ranks use the publication's universe ("of 28" NFL teams, not 32); the sport rail and statistic chips come from today's data, so NBA appears; start times print in the viewer's time zone; the sheet's "Back to list" is a link that closes it. Locked facets (price move since open, teammate out, position-level defense) are notes with their reason, never controls.
