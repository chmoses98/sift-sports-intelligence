Each entry includes player, status, fantasy status, body part, date, the provider&#x27;s injury record id ( injuryId ), the expected returnDate when given, and practice participation (DNP / LIMITED / FULL, with the weekday). Practice participation is parsed from the news note, so it is marked derived: true and is absent when the note doesn&#x27;t say. Note: Populated in-season. Expect a short/empty list in the deep off-season; the NFL report fills in once training camps open. Query Parameters team - Filter to a single team id Example Request curl "https://realtimesportsapi.com/api/v1/sports/basketball/leagues/nba/injuries" \ -H "Authorization: Bearer YOUR_API_KEY" GET /sports/ {sport} /leagues/ {league} /player-availability Coverage note: the league-wide response is truncated by our data provider to the 25 most recent records per team ( limit / page have no effect on it). For a team&#x27;s complete current report — one latest record per athlete, including a structured statusType (e.g. INJURY_STATUS_IR ) — pass ?team={teamId} on this endpoint or on /injuries . Entries with status Active are informational news notes, not availability designations; filter with ?status= . Normalized per-player availability. Each player carries a single availability value — OUT, DOUBTFUL, QUESTIONABLE, PROBABLE, DAY_TO_DAY, INJURED_RESERVE, SUSPENDED, AVAILABLE, or UNKNOWN — so you can gate lineups without parsing free-text injury notes. Query Parameters team - Filter to a single team id status - Filter to a normalized availability value (e.g. OUT) Example Request curl "https://realtimesportsapi.com/api/v1/sports/football/leagues/nfl/player-availability?status=OUT" \ -H "Authorization: Bearer YOUR_API_KEY" GET /sports/ {sport} /leagues/ {league} /player-availability/history League-wide feed of availability changes , newest first. We snapshot the injury report every 5 minutes and record a transition whenever a player&#x27;s designation, injury type, team, report date, expected return date or practice participation changes — including when a player drops off the report ( changeType: "cleared" ). Each record carries previousAvailability so you can see e.g. QUESTIONABLE → OUT. History begins from the date tracking was enabled (NFL: Aug 2026); it is not backfilled. Query: ?team= {teamId} , ?status=OUT (normalized value), ?since=ISO , ?limit= (max 500). Covers NFL, college football, NBA, MLB, NHL. Records observed from Sep 2026 onward also carry the season context at observation time — seasonYear , seasonType (1 pre / 2 regular / 3 post), and week for weekly leagues (NFL/CFB) — so a change can be joined to that week&#x27;s schedule via teamId + week on the events endpoints. Filtering: control what you receive When you subscribe, you can omit filters to get all events of that type, or narrow by sport , league , and/or eventId . The more filters you set, the more specific the stream. No filters — You receive every event of that type across all sports and leagues. sport + league — Only events for that league (e.g. all NFL games, all Premier League games). eventId — Only that single game. Use with sport/league if you want to be explicit. Example sport / league values: football / nfl , basketball / nba , soccer / usa.1 or eng.1 , hockey / nhl , baseball / mlb . Same values as in the REST API. // All score changes, all sports ws.send(JSON.stringify({ type: &#x27;subscribe&#x27;, event: &#x27;event_score_change&#x27; })); // Only NFL score changes ws.send(JSON.stringify({ type: &#x27;subscribe&#x27;, event: &#x27;event_score_change&#x27;, filters: { sport: &#x27;football&#x27;, league: &#x27;nfl&#x27; } })); // Only one game (e.g. play-by-play for event 401772982) ws.send(JSON.stringify({ type: &#x27;subscribe&#x27;, event: &#x27;event_play&#x27;, filters: { sport: &#x27;football&#x27;, league: &#x27;nfl&#x27;, eventId: &#x27;401772982&#x27; } })); // Optional: throttle repeating status (clock) updates (default &#x27;asap&#x27; = immediate) // frequency: &#x27;asap&#x27; | &#x27;30s&#x27; | &#x27;1m&#x27; | &#x27;5m&#x27; | &#x27;10m&#x27; | &#x27;30m&#x27; ws.send(JSON.stringify({ type: &#x27;subscribe&#x27;, event: &#x27;event_status_change&#x27;, filters: { sport: &#x27;hockey&#x27;, league: &#x27;nhl&#x27; }, frequency: &#x27;30s&#x27; })); How frequency works: it only conflates repeating state updates, and it does so per game . With a value other than asap , an event_status_change where the game state does not change (clock, period or detail updates) and event_odds_change are held, and only the latest one per game is sent at the next tick, so you get at most one of each per game per window (e.g. at 30s , at most 120 status updates per game per hour). Ticks are fixed server-side intervals. event_play , event_score_change , event_live , event_final and any status change where status.state changes (pre → in, in → post, Postponed, Delayed, etc.) are always delivered immediately, and a state change discards that game&#x27;s held clock update so you never receive an older one after it. Every delivered message counts once toward usage. An unknown value is rejected with an INVALID_FREQUENCY error and no subscription is created. Webhooks follow the same rules. Events re-sent by a resume replay are not conflated. 5. What you receive: message format Every message from the server is JSON with type and timestamp . For event notifications, type matches the event type (e.g. event_score_change ) and data contains the payload. Example score change: { "type": "event_score_change", "timestamp": "2026-02-18T12:05:00.000Z", "data": { "eventId": "401772982", "sport": "football", "league": "nfl", "name": "Team A at Team B", "homeTeam": { "id": "...", "name": "Team B", "score": 14 }, "awayTeam": { "id": "...", "name": "Team A", "score": 7 }, "previousScore": { "home": 7, "away": 7 } } } Other server message types: subscribed / unsubscribed (after you subscribe/unsubscribe), pong (welcome or response to your ping), error (with error.code and error.message ). Concurrent connections: Free 1, Starter 2, Growth 3, Pro 5, Scale 25 per account. Over the limit, the newest connection gets an error message and is closed with code 4008 ; existing connections are never closed for this. On a monthly paid plan with overage on, you can open extra connections up to 3× your plan&#x27;s limit at $0.02 per extra connection-hour (metered in 6-minute blocks, counted toward your monthly overage cap; on by default, can be turned off in the dashboard). When the cap is reached, new extras are refused and existing extra connections close (newest first); your within-plan connections stay open. Keepalive: The server sends a WebSocket ping every 15 seconds so connections stay open behind proxies. If your client still disconnects after a few minutes, send { "type": "ping" } every 1–2 minutes; the server responds with pong . 6. What are Webhooks? Webhooks allow you to receive real-time notifications when events occur in sports games. Instead of polling our API, we send HTTP POST requests to your server when: A game goes live Scores change Game status changes (scheduled → in-progress → final) New plays occur A game ends Available Event Types event.live Triggered when a game goes live (status changes to in-progress) event.score_change Triggered when the score changes during a game event.status_change Triggered when game status changes (scheduled → in-progress → final) event.play Triggered when a new play occurs in a game event.final Triggered when a game ends (status changes to final) Webhook Payload Format Each webhook request includes the following headers and payload: // Headers X-Webhook-Signature: 3f9a1c... // hex HMAC-SHA256 of the raw body (no prefix) X-Webhook-Event: event.score_change // Event type Content-Type: application/json User-Agent: RealtimeSportsAPI/1.0 // Payload { "event": "event.score_change", "timestamp": "2024-01-15T20:30:00.000Z", "data": { "eventId": "401772982", "sport": "football", "league": "nfl", "homeTeam": { "id": "2", "name": "Kansas City Chiefs", "score": 24 }, "awayTeam": { "id": "3", "name": "Buffalo Bills", "score": 17 }, "status": { "type": { "id": "1", "name": "STATUS_IN_PROGRESS", "state": "in", "completed": false }, "period": 3, "clock": { "value": 1200, "displayValue": "20:00" } } } } Signature Verification Always verify webhook signatures to ensure requests are from Realtime Sports API.
